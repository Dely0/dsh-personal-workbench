# 事故复盘索引（可复用的判据与做法）

> 只收录**有可复用结论**的事故：现象 → 根因 → 那条能防住它的做法。
> 详细的现场记录在各仓库的 `docs/issues/*.md`；这里给"下次怎么避免"。

## 1. 装一个无关插件 → 整机 DSH 起不来（P0 · 2026-09-12）

**现象**：`dsh plugin add @linxin666/dsh-session-archive@0.3.20` 之后重启，
DSH 拒绝启动、GUI 进不去、无法从界面自救。日志：`db schema version 15 is newer than supported 14`。

**根因（两层，第一层最反直觉）**：

1. `dsh plugin add` 是 pnpm 的转发器，会按 `pnpm-lock.yaml` **重新对齐整个 profile** ——
   锁文件里工作台还是 1.12.1（只支持 schema 14），于是已装盘的 1.13.3 被**静默回退**；
2. DSH loader 把 `cordis.patch.yml` 的全部 patch 行当一个**事务组**挂载 ——
   任何一行启动失败 → 整组回滚 → **整个 `dsh web` 进程不起**（不是"这个插件没加载"）。

**可复用做法**：

- 装插件前后各跑一次 `scripts/check-installed-version.mjs`（比对装盘版本 / profile 声明 /
  锁文件解析值 / DB schema / 插件支持 schema）。**pnpm 回退是静默的，直到重启才炸** ——
  这道门禁是唯一能在"GUI 已经起不来"之前抓住它的东西。
- 装完与备份**逐行 diff**，确认只有目标插件一处变化。
- 可选功能插件**没有资格让整个宿主起不来**：库比插件新属运维常态 → 插件侧要**可判别 + 降级**
  （`SchemaTooNewError` + `applyDegraded()`：不注册任何路由/工具，但照常注册 `systemPrompt` 告警）。
- 处置方向：**升级插件，绝不降级数据库**（降库会复活已修的历史事故）。

## 2. 批量删除把"另有职责"的东西一起删掉（2026-09-13 · 同一天连犯两次）

**现象 A**：面板**完全不显示**（用户："插件入口不可用了"）。
**根因**：删 DOM 降级腿时，把 `tokenLayerCss()` 改成 `return ''`（它是全站配色的唯一来源），
并**顺手重写**了 `panelContainerCss()` —— 新版按 `.wb-panel-host` **类名**门控，
而真正承载内容的节点带的是 `VIEW_ATTR`（属性），按类名门控等于什么都没放行。

**现象 B**：工作台**盖住整个 DSH（含侧栏）**（用户："侧边栏都没有了"）。
**根因**：`.wb-panel-host` 用 `left: var(--wb-sidebar-w, 0px)` 定位，而该变量由
`syncSidebarWidth()` 运行时量出、**只在 `apply()` 时被调用一次** ——
那一刻宿主界面还没渲染、侧栏不存在 → 变量从未写上 → 兜底 `0px` 生效。
原先有个 `MutationObserver` 会让它被反复调用，**被我随 DOM 腿一起删了**。

**可复用做法**：

- 删之前列**调用点清单**：对每个待删符号问"谁在调用它"，确认这些调用点是否都随该功能消失；
  只消失一部分 = 它还有别的职责。
- **不要"顺手重写"与 DOM/样式强耦合的门控**；要改就单开一次改动、单开一次验证。
- **绝对定位的兜底值选"最坏情况可接受"**：`0px` 会盖住侧栏，`280px` 只是边界偏一点。
- 依赖"运行时量出来的值"的功能，必须保证**有重试路径**（等目标元素出现）。
- 补了盯防测试：`test/panelCss.test.mjs`（令牌层非空 / 门控按 `VIEW_ATTR` 放行 /
  左边界兜底不为 0 / 量宽必须重试到量到为止）。

## 3. 测试脚本恒过，把真问题盖住（2026-09-13）

**现象**：所谓"主验收脚本"长期输出 `9/9 通过`，而侧栏明明有两个入口。

**根因**：`check()` 的形参写成 `(id, name, ok, detail)`，而全部 9 个调用点都按
`(id, 条件, 说明)` 传参 → `ok` 实际收到的是**说明字符串**（永远真值）。
同一形参错位还存在于另外 15 个脚本里。

**可复用做法**：

- 改判据脚本时**先故意制造一次失败**，确认它会红 —— 只会绿的判据等于没有判据。
- 用同一份脚本的其它判据交叉验证（例：入口数、`data-open`、可见矩形三者要一致）。
- **架构一变就扫一遍验收脚本**：删除某行为后，断言该行为的旧判据会变成**假阴性**，
  看起来像回归。要么反转判据并写清原因，要么加醒目的失效标记。

## 4. 客户端"改完刷新即可"是错的（2026-09-13）

**现象**：改源码 → build → 刷新浏览器，行为没变；有人据此怀疑代码没生效、继续改代码。

**根因**：`dsh-client-modules` 的 `bundleResource()` 只从**宿主启动时**建好的内存 Map 取 bundle；
刷新页面拿到的是旧 bundle，连 URL 上的 `rev` 都对不上（旧 revision → 404）。

**可复用做法**：客户端与服务端改动**都要重启宿主**；把多个阶段合并到同一次重启里验证。

## 5. 同版本号 tgz 被 pnpm 缓存复用（2026-09-12）

**现象**：修完 bug 重新打包安装，行为**完全没变**；看文件时间戳又是新的。

**根因**：pnpm store 按「包名 + 版本号」内容寻址 —— 同名同版本的 tarball 即使内容变了也复用旧副本
（`--force` 无效；Windows 解包保留 mtime，看时间戳判断不出来）。为此白验了两轮。

**可复用做法**：**换了构建产物必须换版本号**；"装的到底是不是新代码"只认
`scripts/check-installed-fingerprint.mjs`（逐文件 SHA256 比对开发树 `lib/` 与 profile `node_modules`）。

## 6. 发布早于验证（v1.13.0）

**现象**：npm 上已经是最新版本，本机还没验证；用户升级后前端直接 `Failed to load plugins`。

**可复用做法**：清单第 2–3 步的顺序不可调换 —— **先本机装盘验证 + 真实浏览器验证，再发布**。
发布后还要复核一次 `check-installed-version.mjs`（确认发布动作本身没改 profile）。

## 7. 两级 inject：硬依赖与可选依赖必须分清

**现象**：低版本宿主上整个插件加载失败（前端 `Failed to load plugins`）；
另一次是标题栏入口直接读 `ctx.slots` 而崩。

**根因**：cordis 的 `inject` 语义是"缺一个就整个插件 pending"，
把它当"可选依赖"用 = 在旧宿主上整体加载失败；而**未声明 inject 的服务用 `ctx.get` 也拿不到**
（`ctx.get('layout')` 永远 undefined）→ 早期实现因此误判"宿主不支持"并静默降级到自建 DOM 腿。

**可复用做法**：

- **前置条件**（面板功能离不开的 `slots` / `layout`）→ 进 `inject`，缺了就**明确不启动**并打可读日志；
- **可选增强**（`uiWorkspace` / `dshIm` / `skills` / 内部记忆服务）→ 一律 `ctx.get()` 软探测，
  缺了只是少一个能力；
- 两者都不要写成"探测失败就换一条腿"—— 那会引入第二套状态所有权（见事故 2、8）。

## 8. 同一个语义被独立计算多次（bug 2 / 6 / 9 的共同根因）

**现象**：点宿主官方行 → 中央一片空白；被兄弟插件挤掉后**再也打不开**；低版本上**永不显示**。

**根因**："面板该不该显示"在三个地方各算一遍，**读的输入还不一样**：
面板容器用 `hasPanelInfoHook()+槽位 props`、`isDisplayed()` 用模块级标志+镜像、
标题栏按钮用 `usePanelInfo+isHostSelected()` → 三处逻辑上可以互相矛盾。

**可复用做法**：

- 把判定抽成**唯一权威源**（纯函数 `panelState.ts` 的 `decidePanel()`，决策表穷举 + 表驱动单测），
  所有调用点（渲染条件、`data-open` 投影、订阅回调、按钮高亮）都走它；
- 加**源码级扫描测试**禁止再内联判定（"不存在第二处实现"只能用源码扫描证明）；
- 同一招也用于"不许碰兄弟插件属性"（I4/I5/I6）：把政策变成**会失败的约束**。

## 9. 写兄弟插件的 DOM 属性 / 摘 `data-dsh-*-active` 误伤别人

**现象**：皮肤中心的壁纸被弄坏（它用 `MutationObserver` 监听 `data-dsh-wallpaper-active`，
一被摘就卸载壁纸且不恢复）。

**根因**：为了与兄弟插件互斥，按**属性名格式**（`data-dsh-*-active`）整片操作别人的 DOM ——
而同一个格式被不同插件表达完全不同的状态。

**可复用做法**：

- **不做跨插件 DOM 协调**；互斥交给宿主的单值状态（`activePanelId`）。
- 精确归因：那些不走官方槽位的插件，宿主无从知晓它们 —— **责任在对方与宿主**，
  写成"我们的缺陷"会误导用户（README / Release Notes 都要写准）。
- 只写自己的属性，并用命名空间前缀 + 源码扫描（写了别家前缀 → 测试红）。

## 10. `MutationObserver` 的 `attributeFilter: []` 一个回调都不触发

**现象**：家族互斥观察器与入口行高亮观察器**双双是死代码**（"两个入口可以同时被选中"）。

**根因**：原实现 `return []` 并注释"空数组 = 观察全部属性"—— **注释是错的**。
Chromium 上 `attributeFilter: []` 是空集合过滤器 → 什么都不匹配 → 0 次回调。

**可复用做法**：要"观察全部"就**省略该字段**（或传 `undefined`）。
读代码完全看不出问题（观察器建了、回调也对）—— 只有实测能发现回调根本不触发。

## 11. 渲染期做副作用 / 写 DOM

**现象**：面板打开后整个页面卡死；槽位条目干脆不渲染（页面里查不到容器）。

**根因**：在组件体（渲染期）里写模块级状态 / 写 `document.documentElement` 属性，
以及 `createRoot().render()`。React 在 concurrent 渲染下会重复执行或丢弃渲染期副作用，
"写属性 → 触发观察器 → 再触发渲染"的回路会把主线程占满。

**可复用做法**：**所有副作用一律进 `useEffect`**，并保证 DOM 写入**幂等**（同值不写）。
幂等也是防"写 → 观察器 → 再写"永不收敛的唯一手段。

## 12. 静默降级铺满屏层，把整个界面盖住

**现象**：用户"除左栏外什么都点不了"。

**根因**：探测不到官方槽位就降到自建 DOM 腿，而那条腿铺了一张
`position:fixed; inset:0; z-index:55` 的**满屏层**，收不起来就永久盖住会话区。

**可复用做法**：

- 能力不满足时**明确不启动**并打可读日志（含"缺什么 + 要求什么版本"），而不是半死不活地降级；
- 任何覆盖层都要有"空的时候不拦点击"的兜底（`:empty { pointer-events: none }`）；
- 覆盖层的位置要**避开宿主导航**（用运行时量出的侧栏宽度，不硬编码）。

## 13. 在真实数据上跑"会写库"的验收脚本

**现象**：差点在用户的真实库（50 条任务）上跑会造任务/草稿的验收脚本。

**可复用做法**：跑之前**grep 脚本有没有写操作**（`POST`/`PATCH`/`DELETE`/`/confirm`/`/defer`）。
只读的可以直接跑；会写数据的要么先备份库，要么造隔离实例（独立 `DSH_HOME` + 独立库 + 独立端口）。
**在真实库上删数据前**：备份 + 把待删行导出成回滚 JSON + 先 dry-run 打印将删什么，再 `--apply`。
