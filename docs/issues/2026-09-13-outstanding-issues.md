## P1 · 会影响判断的可信度（优先处理）

### P1-1 `.pwtest/` 里仍有一批"架构变更前"的脚本（含 4 个真会误报的验收脚本）

- **现象**：`.pwtest/` 下 80 个脚本是长期迭代产物。家族互斥与 DOM 降级腿已在 v1.14.53 删除，
  其中一部分脚本仍在测**那些已经不存在的行为**，跑起来必然失败或给出误导结论。
- **实测扫描（2026-09-13）**：按关键选择器扫了一遍，结论要分清两类 ——

  | 类别 | 关键词 | 结论 |
  |---|---|---|
  | **仍然有效** | `.wb-panel-host`、`sidebarCol`、`centerCol` | ✅ 这些是**现役**结构（面板容器类名、宿主侧栏/会话列类名），命中的脚本不必改 |
  | **已失效** | `data-dsh-taskboard` / `data-dsh-ssh` / `data-dsh-mnemon`、`dsh-panel-activate`、`BLOCKED_ATTR` | ❌ 家族互斥协议已删，测这些行为的脚本会误报 |
  | **已删除的路径** | 脚本名/注释里的 `DOM 降级腿`、`domleg` | ❌ 那条腿不存在了 |

- **需要优先处理的 4 份**（它们看起来像"能用的验收脚本"，误报代价最大）：

  | 脚本 | 问题 |
  |---|---|
  | `.pwtest/verify-mutex-family.mjs` | 测"家族互斥让位"——该行为已删除 |
  | `.pwtest/verify-board-takeover.mjs` | 模拟 task-board 契约并断言"工作台让位"——同上 |
  | `.pwtest/verify-board-overlap.mjs` | 同上（面板重叠由宿主 `activePanelId` 保证，不再由我们处理） |
  | `.pwtest/verify-stable.mjs` | 注释与判据都含"降级腿"形态 |

- **已处理的一处（可作模板）**：`.pwtest/verify-acceptance.mjs` 的 ⑤/⑤b/⑥ 已**反转判据**
  （从"兄弟标记出现→我们让位"改为"兄弟标记对我们无效、我们也不改它的属性"），
  并在脚本里写清为什么反转；改后 17/17。
- **风险**：下一个改客户端的人会先跑 `.pwtest/verify-*.mjs`，撞上一堆假失败，
  很可能**误判成真实回归**（交接文档第 8 节第 4 条正是这个坑："架构一变，旧判据就变成假阴性"）。
- **建议方向**：要么按 `verify-acceptance.mjs` 的方式反转判据，要么在这 4 份脚本头部
  加一行醒目的 `// ⚠️ 架构变更后失效：测的是已删除的家族互斥，勿作判据`，
  再考虑加一个 `scripts/check-verify-scripts.mjs` 扫描过时关键词并告警。

### P1-2 `.pwtest/verify-draft-survives-panel.mjs` 的步骤③④判据不稳（非 UI 缺陷）

- **现象**：该脚本第 1 轮第 ⑤ 项稳定通过（**重新打开面板后连续 10 次采样弹框都在**），
  但步骤③（唤回）④（返回对话）时常报失败。
- **已诊断的原因**：不是 UI 问题，是脚本自己的取点/断言方式不够稳 ——
  「唤回处理」按钮在 `待你处理` 弹框内（弹框标题带全角括号，前缀匹配可用但时机敏感）；
  「返回对话」按钮文本含 `<span>`，用文本匹配取点心不稳；多轮之间面板开合状态未归零
  （侧栏入口是**开关**，上一轮留着开，下一轮再点就变成关）。
- **影响**：不影响产品行为，但会掩盖真实回归（和 P1-1 同类风险）。
- **建议方向**：按 `verify-duplicate-task.mjs` 里已验证的写法重写 ——
  用 `[role="dialog"]` + `<h3>` 标题分类定位弹框、每轮开始先"确保面板是关的"再点开并校验 `data-open`。

## P2 · 产品行为：已确认但不打算改（想改时再做）

### P2-1 「回到…会话」之后弹框不再自动出现（"回工作台自动复活"未做）

- **背景**：用户早先实测"弹框暂存 → 唤回 → 点「回到执行会话」→ 5 秒后弹框消失"。
  **"5 秒"那一半已修**（v1.14.52：新增 `onSettled`，让横幅**同一帧**收掉，
  不再等下一轮 5 秒轮询覆盖）。
- **现状**：点「回到…会话」仍会把该草稿记进"看过就收起"的屏蔽集合
  （`dismissedDraftIdsRef`），因此**回到工作台时它不会再自动弹**；
  草稿本身仍是 pending，能在「待处理」里找到并重新打开。
- **为什么先不做**：用户 2026-09-13 明确判断 —— 关闭逻辑本身是合理的，
  而"回工作台自动复活"属于**新功能**，在缺少测试锁定的状态下不宜顺手加。
- **建议方向**：若要做，把"该显示哪一份草稿 / 屏蔽谁 / 屏蔽多久"抽成
  **与 `panelState.decidePanel()` 同规格的纯函数选择器**（无 DOM、可 `node --test` 直接测），
  并区分两种意图：`我永久收起它`（点 X / Esc → 保持屏蔽）
  与 `我只是去别处看看`（回到会话 → 仅临时收起，回工作台应恢复）。
  详见任务共享记忆里的决策记录。

### P2-2 `lastDraftIdRef`（防"弹框静默换人"用）可能残留

- **现象（代码审阅，未实测）**：`src/client/index.tsx` 里用于识别"递补换人"的 ref
  只在某些分支更新，草稿从列表消失时不清空；下次换人判断可能因此误报或漏报。
- **触发条件**：需要同时存在多份 pending 草稿、且其中一份被暂存/放弃，概率不高。
- **建议方向**：并入 P2-1 的状态收敛一起做（同一个状态机里表达"当前展示的是哪一份"）。

### P2-3 与"以 DOM 接管中栏"的兄弟插件仍可能同时激活

- **现状**：这是**有意的取舍**，不是缺陷。面板互斥由宿主 `activePanelId` 保证；
  `dsh-client-ui-task-board` / `dsh-ssh` / `dsh-mnemon` 不使用官方槽位，
  宿主的互斥链条里就没有它们。
- **已在 README 写明准确归因**（"面板互斥与兄弟插件冲突"一节），
  并在 `test/clientInvariants.test.mjs` 里用 I5 锁住"我们不碰它们的属性"。
- **若将来要改**：不要走回"按格式摘 `data-dsh-*-active`"的老路（2026-09-13 因误摘皮肤属性
  弄坏过壁纸），要先确认宿主是否提供统一的第三方面板注册机制。

## P4 · 流程教训（写下来免得再犯）

### P4-1 批量删代码前必须先列"调用点清单"（两次真实事故）

v1.14.53 的架构阶段 2 删了约 700 行（DOM 降级腿 + 家族互斥），过程中**两次**删过头：

| 版本 | 删掉了什么 | 后果 | 怎么修的 |
|---|---|---|---|
| 1.14.54 / 1.14.55 | `tokenLayerCss()` 被改成 `return ''`；`panelContainerCss()` 被**重写**成按类名门控 | 令牌层消失 + 面板**完全不显示**（用户："插件入口不可用了"） | 从 `v1.14.53-stable` 逐字恢复，并对每个幸存函数做逐行比对 |
| 1.14.56 | 唯一会**反复**调用侧栏量宽的那个 `MutationObserver` 被一起删掉 | `--wb-sidebar-w` 从未生效 → 兜底 `0px` → **工作台盖住整个 DSH（含侧栏）** | 量宽改为"重试到量到为止"，兜底值改 280px |

**可复用做法**：
1. 对每个待删符号列出**谁在调用它**，逐个确认这些调用点是否都随该功能一起消失；
   只消失一部分 = 它还有别的职责，不能删。
2. **不要"顺手重写"与 DOM/样式强耦合的门控**（那不是删除，是改写）。
3. 绝对定位的**兜底值要选"最坏情况可接受"的那个**（`0px` 会盖住侧栏；`280px` 只是边界偏一点）。
4. 测试要盯**生成物**而不只是逻辑：`test/panelCss.test.mjs`（8 例）现盯"
   令牌层非空 / 门控按 `VIEW_ATTR` 放行 / 左边界兜底不得为 0 / 量宽必须重试到量到为止"。
5. 重构后**旧验收脚本会变成假失败**，要反转判据并写清原因（见 P1-1）。

### P4-2 客户端改动必须重启 `dsh web` 才生效（不是"刷新即可"）

- `dsh-client-modules` 的 `bundleResource()` 只从**宿主启动时**建好的内存 Map 取 bundle
  （`lib/index.js:857-871`），所以"改源码 → build → 刷新页面"**拿不到新代码**；
  连 URL 的 `rev` 都对不上（旧页面请求的是旧 revision → 404）。
- 正确流程：改版本号 → `pnpm build` → `pnpm pack` → `dsh plugin add <新 tgz>` → **重启**。
- 交接文档里"客户端改动刷新即生效"那句话是**错的**，已在本轮实测推翻。
