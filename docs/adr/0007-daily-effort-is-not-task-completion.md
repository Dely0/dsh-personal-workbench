# 今日投入结束与任务完成分离

**Status:** accepted（2026-09-30，用户在本次需求补齐中明确选择推荐方案）

## 决定

长任务可以跨日分配投入。因此某日计划项的“今天这部分做完/今天不再做”与整个任务完成不是一件事。本轮新增独立 `effortDone`，存在 `daily_plans.items_json`，不新增任务状态。

- “今日投入结束”只设当天项 `effortDone=true`；“继续投入”只设 false。
- 不修改任务进度、截止、估时、状态；不触发父子级联。
- “完成任务”是另一个明确动作，保持用户直接完成/AI提交验收的现有路径。
- 不把分钟数当作实际工作量，不自动按投入/估时累加进度。
- 容量“已排”包含当天全部计划投入，结束/关闭任务不会自动释放已排；移除计划项才减少。
- 同任务另一天的项独立，新项=false。历史计划只读。
- 原“明天”动作改名“推迟截止一天”并保留改 dueAt 的语义，不声称它移动计划项。

## Considered Options

- **本轮仅加分钟，不加计划项状态**：改动较少，但跨日长任务仍无法表达今天这一段结束；用户本次明确未选。
- **沿用计划“完成”直接完成任务**：不能解决长任务，容易误完成整个父任务并触发级联。
- **按日投入自动增加任务进度**：投入不等于有效产出，破坏 ADR 0004 的显式权威源。

## Consequences

S5/S6 扩为分钟快照、独立结束状态、局部 UI 与 API 全链路；S4 只接显式进度建议，不引入自动推算。字段与历史回填见 [开发规格](../tasks/36c8e8ef-1104-4e68-b55f-a2a6cc533ab9-工作台插件优化/requirements.md) R-D/R-C，验证见同目录 acceptance.md。任务原批次 1 的“不碰页面结构”表示不做 S14，并不排除这些局部交互。
