# 工作台专家：生成草稿、确认安装与子代理调用

**Status:** proposed（用户要求按评审结论细化；实施规格待评审，尚未实施验收）。

关联任务：51189a57-04c0-4b8a-811c-945703cc9850。

完整实施契约：[方案 v0.3](../tasks/51189a57-04c0-4b8a-811c-945703cc9850-工作台专家功能实现和优化/方案-v0.3.md)。施工和验收见同目录 implementation-plan.md、acceptance.md、verification.md。

## 背景

用户需要方便地创建适合自己的中文专家，并在新会话或当前会话中使用。现有工作台已提供本地人格解析、三级来源、固定会话绑定和草稿确认；但不能直接支持“专家和技能文件确认安装”或“另一位人格的子代理调用”。

产品定位转为 AI 辅助生成，减少每个上游专用转换器、镜像与持续同步的维护。对上游的复制/改写仍须保留对应版权和许可材料。

## 决定

1. 主入口为专用生成会话；直接 sessions.create({workspaceId})，投递随包方法论及用户需求。不复用已有任务或 blank 会话。
2. 草稿 kind=expert，状态沿用 pending/confirmed/abandoned，payload 有 schema/version/校验清单。只使用已有 DB 表与 meta、字典种子，不新开 migration。
3. 生成工具只提交/暂存/校验；正式文件由用户确认路径安装。ID 为 generated/<服务端 UUID>，不随来源/名称变化。
4. 安装按 journal + SQLite 确认结果 + publication.ready 恢复。commit 前补偿自己拥有的文件，commit 后完成发布；不把 SQLite 回滚等同于文件回滚。
5. skill 使用工作台 provider，rank=600；实际 winner 还受 scope 层影响。安装后 invalidate，用户同名技能保持优先。
6. 普通新会话维持 ADR 0005 的固定 persona 绑定与按需读取。中途召唤使用官方本地 spawn；短 persona 指令让子代理通过专用 ticket 工具加载正文/附件，不修改父绑定。
7. 手动 @ 与 /expert 生成受会话约束的 request，复用一个服务端执行器。自主 summon_expert 的 schema、清单和执行权独立默认关闭。
8. 来源登记为版本化 provenance + 全部上游版权/许可原文。MIT 字样、repo/commit/日期不是许可原文的替代品。本期复制素材仅支持已明确 MIT 的来源。
9. 管理页同时展示可用、停用、格式错误、依赖不可用、未完成安装；状态从磁盘/配置/宿主能力推导，不另存可用状态表。
10. 可选服务软注入；缺失时对应增量明确降级，不让整个工作台 pending。

## Considered Options

- **生成会话 + 校验安装（选中）**：保留个人工作流，机器保证格式、目录、发布和恢复；模型仍负责选材与改写判断，用户审阅来源与正文。
- **按上游逐条同步**：需维护转换器、资源包和可达性，本次用户已选择生成流程；不纳入本期。
- **子代理全文 persona**：实现短，但正文进入 prompt 模板且附件加载仍不闭合；选择短指令 + 专用加载工具。
- **预建普通子会话绑定**：需介入官方 start 前的生命周期；公开请求没有 setup 回调，另造启动器会扩大维护面。
- **下载 skill 逐条 runtime register**：固定 rank=250，会盖过 rank=400 用户技能；不符合优先级要求。
- **只复用现有 withDraftConfirm**：事务不能回滚 FS，不能保证跨目录与 DB 一致；必须补安装日志和发现门。

## 对 ADR 0005 的影响

- 保留 Markdown 形态、20000 UTF-16 正文上限、三级来源及优先级。
- 保留普通工具无 persona_id/session_id 参数、来源/revision 固定、“换角色新会话”。
- 本期扩展：用户确认可写用户人格根，新增受管发布门与专用子代理 ticket 加载；内置、外部仍只读。
- 正文仍按需通过工具读取，不向所有 prompt 填人格全文。
- personaExternalDir 保持单 string；未证明需要多根升级。
- 本 ADR 被接受后，应在 ADR 0005 补一条链接说明上述扩展，不直接删掉历史决定。

## Consequences

- 增加安装器、恢复日志、provider、子代理适配器、来源登记和 UI，而非仅增加一个按钮。
- 复制 skill 需要普通 YAML 解析库；使用公开可选 scope helper，避免错误地忽略 scoped 技能覆盖。
- 首期仅新建、文本包、前台一次性子代理；覆盖/删除、二进制包、后台续聊、推荐市场后移。
- future 官方通道出现时可替换宿主适配器以降低迁移成本；不承诺未知契约下绝无数据迁移。
- 验收分别检查静态/单元、真实 SDK、浏览器和真实 LLM。模型未加载人格不得报告专家调用成功。
- 0008 已有另一项 accepted 决策，本方案使用 0009；如并发工作占用编号，提交前统一改为下一个空号。

## 接受条件

用户评审完整规格；实现满足 acceptance.md 的必需断言并如实记录未验证项。届时修改本状态为 accepted；现在不预先宣布验收通过或发布。
