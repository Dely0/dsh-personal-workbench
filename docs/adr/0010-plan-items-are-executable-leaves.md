# 计划项必须是可执行叶子（父任务排入今日 = 展开子树）

**Status:** accepted（2026-10-05，用户在本轮讨论中明确选择方案 A；"父任务自己也要投入"明确选择不开口子）。

修订 [ADR0002](0002-capacity-reads-daily-plan.md) Consequences 里"父子链冲突明确拒绝"一行；容量口径本身不变。

## 背景

用户报的两个现象（2026-10-05）：

1. 未排期的**父任务**点「排入今日」后，它下面的子任务没有排进今日计划；随后再点那些子任务，会**报错**。
2. 未排期的**子任务**先被排入今日后，它的父任务点「排入今日」也**报错**。

两者同源，都是 `src/shared/dailyPlanPolicy.ts` 的 `checkPlanTaskSet` 第 4 条「同一父子链不能同时列入计划」（判据 `isTaskWithinSubtree`）。这条规则当初是为"已排 = 当日计划项 minutes 之和"不被父子重复计数而设的兜底（ADR0002），它没错，但它**没有回答"排期父任务意味着什么"**。

同时存在一条与口径无关的缺陷：日期面板「计划」树只保留命中项的**祖先**、不保留后代（`src/client/taskFilterSort.ts` 的 `filterTaskTree`），而「未排期」成员是补集（`src/shared/dailyPlanPolicy.ts` 的 `dayPanelTabMembers`），于是父任务排入后，子任务既不在「计划」里、又留在「未排期」并继续拿着一个点了必然 400 的按钮。

## 决定

**计划项必须是可执行叶子。** 一个任务是**叶子**，当且仅当它下面没有未完成（open）的子任务；只有叶子有资格成为某日计划项。这条硬校验只实现一次（`checkPlanTaskSet`），由四条写入路径共用：`POST /plans/:date/items`、`PUT /plans/:date`、AI 草稿确认、AI 排序工具。

**「排入今日」在非叶子上 = 展开子树。** 手工一键排入入口（`POST /plans/:date/items`）把目标节点下所有未完成叶子按树序（先父后子、同级沿用现有排序）依次追加进该日计划，每个叶子取自己的预计耗时 / 设置默认投入。

- **父任务本身不进计划项、不占容量**。它在「计划」页签里作**分组行**（沿用已有上下文行形态）显示，写「N 个子任务 · 合计 X 分钟」，X 只是子项之和，不再加父任务自己的估时（父任务通常没填估时，加了就是"30 分钟"这种假数字）。
- **幂等且不覆盖**：已在计划里的叶子原样保留（minutes 与 effortDone 都不动，沿用现有 `added:false` 语义）；重复点父任务只补齐还没排的叶子；子任务先排、父任务后来点不再报错。
- **回执必须回显服务端实际落库的内容**：展开了哪几条、各自投入多少分钟。服务端替用户展开了什么必须说出来，禁止静默改写。
- **历史脏数据保留原样**：库里已存在的"父任务作为计划项"不自动清理（沿用 ADR0002「不替换已有项」与迁移期只做加法的约定），照旧显示与计容量。
- **「未排期」页签的成员判据随之改为「今日未安排」** = 自己不在计划、且**子树里也没有计划成员**（排期状态按子树继承）。于是子任务已排完的父任务自动离开「未排期」，那个必然失败的按钮随之消失；还有没排的叶子的父任务留在「未排期」，按钮 = 把剩下的叶子补齐。三页签「并集 = 全部 open 任务」的划分性质不变（`plan` 与 `overdue` 的事实重叠也照旧）。
- **「父任务自己今天也要投入」不开口子**：有未完成子任务时它只能是分组行。要亲自做的那部分写成子任务（拆解本来就是工作台的能力），或等子任务完成后再排它自己。

**AI 草稿确认 / 全量保存路径不展开**：非叶子项整份拒绝并给可读原因（沿用 `docs/tasks/36c8e8ef-1104-4e68-b55f-a2a6cc533ab9-工作台插件优化/requirements.md` 里"草稿确认整份拒绝并保留草稿"的既有条目）。不替用户或 AI 猜他要排哪几个子项 —— 展开只发生在用户**点了父任务那一行**的一键排入上。

## Considered Options

- **A 展开到叶子（选中）**：与 AI 排序提示词本来就采用的"只排可执行的叶子"口径统一（`src/tools.ts` 的 `workbench_propose_daily_plan` 工具描述、`src/client/hooks/useWorkbenchAISessions.ts` 的计划提示词）；容量继续只有"计划项之和"一个口径，不引入"父项计 0"这类例外；父子链互斥规则不必删除 —— "非叶子不进计划项 + 排入时展开"让它天然成立。
- **B 整链共存**（父与子都进计划项）：需要另定父项投入口径（计 0 / 只算父 / 全算），全算即同一份工作在容量里算两遍，计 0 则让"计划项"一词同时表示两种东西；用户未选。
- **C 自动替换不报错**：后一次操作把冲突方移出计划；改动最小，但与 ADR0002「不替换已有项」及本仓库"不擅自替用户改历史决定"冲突；用户未选。
- **D 只修显示与死按钮**：保留现有排入语义，仅让后代在「计划」页签灰显、隐藏必然失败的按钮；「排期父任务 → 子任务都排进去」的诉求未实现；用户未选。
- **给父任务留一条自己的投入**（容器行计 0 / 占容量）：前者让"计划项"同名不同义，后者重复计数；用户明确选择不开口子。

## Consequences

- ADR0002 的"父子链冲突明确拒绝"被本文修订：一键排入不再拒绝，而是**展开到叶子**；"不替换已有项"仍然成立。
- 容量口径不变（仍只算计划项 minutes 之和）：叶子是唯一合法计划项，"父子重复计数"在结构上不可能发生。
- `isTaskWithinSubtree` 与"同链互斥"继续保留给**历史脏数据**（既有项豁免语义不变：两项都在既有计划里时不因本次无关写入被拒）。
- **给已在今日计划里的任务新增第一个子任务**仍会被拒（父项是既有计划项、子项要新增）。这一条要换成可读原因 + 界面提示"先移除父项"，不许留必然失败的入口。
- 「计划」页签的分组行不计入计划条数（与「已完成」页签对上下文行同一条规矩）；「逾期」/「未排期」页签的父行允许挂一键排入（动作作用于它下面还没排的叶子）。
- 本机数据不需要迁移。
- 待同步的既有口径：`docs/tasks/36c8e8ef-1104-4e68-b55f-a2a6cc533ab9-工作台插件优化/requirements.md`（当年写死的"同一父子链不能同时入计划"判据）、`docs/adr/0001-today-is-the-day-panel.md`（日期面板树来源口径）、`src/tools.ts` 与 `src/index.ts`（AI 工具描述里的"同一父子链不要同时入列"）。实现时同步。

## 判据（实现前先写成会失败的测试）

1. **叶子判定**：`checkPlanTaskSet` 新增项为**非叶子**时必拒且给中文原因；两条**兄弟叶子**允许；"两项都在既有计划里"的历史豁免仍然成立。
2. **展开函数**（`src/shared/dailyPlanPolicy.ts` 新增纯函数，暂名 `expandTaskToPlanLeaves`）：父 → 全部未完成叶子，按树序（先父后子、同级沿用现有排序）；跳过已 done/cancelled/归档的子任务；含多层（中间节点自己也带子任务）；无子任务的节点 → 它自己。
3. **一键排入端到端**：父任务排入后计划里出现全部叶子且各带自己的 minutes；重复调用 `added:false` 且不改动已有 minutes/effortDone；子任务先排、再排父任务 = 只补缺口。
4. **页签划分**：父任务在部分叶子已排时仍在「未排期」（成员是未排叶子，父是上下文行）；全部叶子已排后父任务离开「未排期」；`dayPanelTabMembers` 的"并集 = 全部 open 任务"性质断言保持绿。
5. **单一实现扫描**：不存在第二处父子链/叶子判定 —— 一键排入、AI 草稿确认、全量保存共用同一份 `checkPlanTaskSet`。
6. **界面**：「计划」页签对全部叶子已排的父任务渲染分组行与合计、且**不给**「排入今日」按钮；「未排期」页签的父行可一键补齐剩余叶子；历史上"父项已在计划里"的边界给出可读原因而不是裸 400。
