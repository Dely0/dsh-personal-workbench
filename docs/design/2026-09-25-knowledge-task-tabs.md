## 0. 定稿（与最初需求相比改了两处）

用户看过 4 款打样后选的是：

| 页面 | 款式 | 定稿说明 |
|---|---|---|
| **知识库** | ① 密集列表 + 时间分组 | 分类从下拉改成 **Tab 页** + 搜索 + 标签筛选 + 排序 + **50/页分页** |
| **点子** | ① 卡片瀑布（Bento） | 文件夹区**完全不动**，只把下面的点子卡片改成 2 列网格 |
| 任务列表 | — | **本轮不动**（现状已有筛选/排序） |

打样与调色板：`demo/kb-styles/`（4 款 + 画廊页）、`demo/kb-styles/ideas-gallery.html`（点子页确认稿）、
截图在 `_local-archive/kb-styles/`。

**两处与最初需求的偏差（都是刻意的）**：

1. **时间分组必须自适应**：真实库里 59 条有 49 条在同一天，硬分组会出现「今天 1 / 本周 0」这种空壳组头。
   现在**条目数 < 6 的组并回更旧的那一组**，并取更旧那一档的名字（名称语义 = "这批里最旧的到哪一档"）。
2. **知识库的搜索/筛选/排序/分页全部在客户端做**，只向服务端要一次全量。原先"每次筛选都请求一次"
   在千级规模下等于每敲一个字打一次库。

## 1. 问题

分类形态是**下拉列表**：

- 知识库：`<select>` 有「全部分类 + 4 个知识类型」；
- 任务列表：状态 / 优先级 / 类型**三个多选下拉**，其中类型 9 项、状态 6 项、优先级 4 项。

条目变多以后，下拉的毛病是结构性的：

| 毛病 | 后果 |
|---|---|
| 选项藏在折叠里 | 扫不到"有哪些分类"，更看不到"每类有多少条" |
| 一次只能看一个维度 | 想"先看经验教训，再看决策记录"必须反复开合菜单 |
| 长列表要滚动着找 | 9 项类型要滚动，眼动成本随分类数线性增长 |
| 没有搜索 / 标签筛选 / 排序 / 分页 | 1000 条时只能靠肉眼翻，没有可收敛的漏斗 |

## 2. 设计（交互原型已实现）

原型顶部有三个开关：**视图**（知识库 / 任务列表）、**形态**（Tab 新 / 下拉现状 / 并排对比）、**数据量**（120 / 1200 / 3000）、**长列表**（分页 / 虚拟滚动）。

### 2.1 Tab 分类（核心改动）

- 下划线式 Tab，选中项加粗 + 蓝色下划线 + 浅色底，**每项带条数徽标**。
- 知识库 = `全部 + 笔记 + 经验教训 + 决策记录 + 片段/模板`（5 个）。
- 任务列表 = `全部 + 9 个任务类型`（10 个）。
- **超过 10 个**自动折叠尾部进「更多 ▾」，展开后 `overflow-x` 横向滚动（不换行、不挤压列表高度）。
- Tab 条数 = **当前搜索 + 其他筛选条件下**该分类的命中数（所以筛选后条数会一起变，这是对的：它回答的是"切过去能看到几条"）。

### 2.2 Tab 状态保持（验收项）

- 写本地存储：`dsh.personal-workbench.tab.knowledge` / `…tab.tasks`（值 = 分类 code）。
- 刷新 / 重开面板 / 切走再回来都保持；排序键与方向同样持久化（`…sort.*` / `…sortDir.*`）。
- 原型里已实测：点「笔记」→ 存储写入 `"note"`，面板上 `#kbRoot .tab.on` 同步。

### 2.3 搜索

- 知识库：**标题 + 正文 + 标签**（三处任一命中）。
- 任务列表：**标题 + 描述**。
- 大小写不敏感；命中片段**高亮**（原型里用 `<mark>`，真实实现用同样的思路）。
- 输入 **200ms 防抖**；1200 条下"敲字 → 出结果"实测 326ms（含防抖），filter 1.4ms。

### 2.4 筛选（可与 Tab、搜索叠加）

- 知识库：**标签**（从现有条目里现算，不新建字典）+「本地文件：有/无」+「关联任务：已关联/未关联」。
- 任务列表：**状态**（6）+ **优先级**（4）；类型已升为 Tab，不再重复做筛选。
- 语义为**同维度 OR、跨维度 AND**；每个 facet 一行 chip，已选项高亮加粗。
- 「清空筛选」只在真的有筛选或关键词时可点（和现有 `isTaskFilterEmpty` 一个口径）。

### 2.5 排序

| 视图 | 可选项 | 默认 |
|---|---|---|
| 知识库 | 更新时间 / 创建时间 / 标题 | **更新时间 ↓** |
| 任务列表 | 更新时间 / 截止时间 / 优先级 / 创建时间 / 标题 | **更新时间 ↓** |

- 方向按钮 `↑ 升序 / ↓ 降序` 独立切换；「截止时间」沿用现有规则：无 `dueAt` 的已完成任务按 `completedAt` 参与。
- 排序键与方向都持久化；稳定的兜底是 `updatedAt DESC, id`（避免等值项乱跳）。
- **注意**：任务列表现在的默认是「截止时间 ↑」，本任务验收要求"默认按更新时间倒序"——**这会改变任务页的默认观感**，实现时会同时保留「截止时间」为可选项。若你希望任务页仍默认按截止时间，请在验收时说一句（一行常量）。

### 2.6 分页 / 虚拟滚动（两种都做，工具条上可切）

- **分页**（默认）：每页 50（可选 50 / 100 / 200），底部显示"第 1–50 条 / 共 1,200 条 · 1/24 页"+ 首尾/相邻页按钮。
- **虚拟滚动**：只挂可视区 ± 6 行。原型实测：命中 1,200 条时 DOM 里只有 **12 行**。
- 两者共用同一份"过滤 + 排序"结果，切换不重算业务判定。

### 2.7 置顶 / 最近使用 —— ⚠️ **本版未实现**（见第 5 节）

以下是原型里的形态，最终没有落地（用户没提这条，且要引入新的本地状态）：

- 每行右侧 `☆ / ★` 置顶（**只写本地存储，不动任务字段**，不改数据库）。
- 置顶区固定在列表上方；「最近使用」= 最近打开的 3 条（与置顶去重），带「清空」。
- 置顶项在排序中**优先于**排序键（`置顶 > 排序键 > 兜底`）。

## 5. 原始需求里被否掉的部分（记录取舍，免得后人以为是漏做）

用户复盘时说："其实我最开始只是觉得知识库页面不好看、没有分页，后面的需求都是澄清出来的，不一定对"。
因此原先澄清出来的一批需求**没有实现**，理由如下：

| 原需求 | 处置 | 理由 |
|---|---|---|
| 知识库 + **任务列表**都改 Tab 分类 | 只做知识库 | 用户定稿只要知识库；任务列表已有筛选/排序，动它属于无谓风险 |
| 标签与**类型**筛选 | 只做标签筛（+ Tab 即类型） | 类型已经升成 Tab，再做一遍筛选是重复入口 |
| **最近使用 / 置顶** | 未做 | 用户没提；且"置顶"要写 localStorage 或加字段，先不引入 |
| 虚拟滚动 | 未做，只做分页 | 50/页分页已把 DOM 行数压到 50，千级规模实测 P95 < 2ms；虚拟滚动收益不足以抵复杂度 |
| 任务侧的"标签"（方案 A/B） | 未做 | 任务列表本轮不动 |
| 任务树 × 筛选 / 分页语义 | 未做 | 同上 |
| 任务页默认排序改更新时间倒序 | 未做 | 同上（原验收要求里的这一条随之作废） |

**验收标准里仍然有效的**：知识库分类用 Tab（不是下拉）、Tab 状态刷新后保持、千级规模不卡顿（有实测证据）、
搜索命中标题与正文、筛选可叠加、排序可切换且默认更新时间倒序、修前/修后对照。
**随之作废的**：任务列表用 Tab、任务页默认排序（见上表）。


### ⚠ 5.1 任务侧的「标签」

任务表（`tasks`）**没有 tags 字段**（只有 knowledge_entries / ideas 有 `tags_json`）。两种走法：

- **A（原型现在这样）**：把任务上已有的**类型 / 优先级 / 状态**徽标当作"标签"并可点选筛选，**不新增数据库字段**。零迁移、零风险，但拿不到 `#内网`、`#TTS` 这类自由标签。
- **B**：给 `tasks` 加 `tags_json`（schema 迁移 16，只追加迁移）+ 编辑界面 + 搜索/筛选带上它。要动数据库与任务表单，工作量大约多 0.5–1 天。

### ⚠ 5.2 任务树 × 筛选 / 分页

- 命中子任务时**保留父链**作为上下文行（淡显、不计入条数）——与现状 `filterTaskTree` 完全一致，不制造无父的孤儿行。
- 分页按**顶层根节点**计数：父任务与其整棵子树不拆到两页。
- 虚拟滚动在树形态下 = 冻结表头 + 窗口化行（展开的子树按展开后的行数算高度）。

这两条如果你没有别的意见，我就按上面写死的语义实现。

## 9. 真浏览器渲染验证（`scripts/repro/harness-real-browser.mjs`）

前面几层各有到不了的地方：`node --test` 的 `renderToStaticMarkup` 只能验证"渲染成什么 HTML"，
**CSS 下的真实布局**不在那里；原型打样页用的是手写假组件；宿主页面缓存着旧 bundle。
所以又补了一层：把**真组件**渲染成 HTML → 配**真实 `WORKBENCH_CSS`** → 挂进 headless Edge
（DOM 结构照真实面板搭：`html[official]` + `.wb-panel-host[data-open=1]` + `.wb-app-scope`）
→ 用 CDP 做布局与命中测试。**24/24 通过**，截图 `_local-archive/listviews/harness/real-render.png`。

**这一层抓到了两个别的层完全看不到的真 bug**（都属于"看得见、点不动"）：

1. **`pointer-events` 继承**：面板宿主 `.wb-panel-host` 是 `pointer-events:none`（为了让左侧导航栏
   在面板铺开时仍可点），而 portal 到 `body` 的菜单会**继承**这个值 —— 菜单画出来了，却收不到任何点击。
