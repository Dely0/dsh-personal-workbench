## 0. 结论速览

1. **有授权的源存在，但不是 WorkBuddy**。`msitarzewski/agency-agents`（MIT）与 `K-Dense-AI/scientific-agents`（MIT）是两个正源；`vbarter/workbuddy-experts` 的 MIT **只覆盖整理工作**，正文版权归上游与腾讯，不可用。
2. **需求粒度：按需同步单个专家，不做全量同步**。第三方专家不同步进插件就不能在插件里用；用户只同步自己需要的几条（预期量级 5–30）。
3. **分组按源**；每源一个独立转换器；**不 fork 上游**。
4. **同步厚度参考 K-Dense 原生形态**（连 `skills/`、脚本一起带），但附件脚本**只读不执行**，UI 必须标注。
5. **命令形态**：不按专家名注册 `/` 命令；实体选择走 `@` 引用源（`ctx.inputTriggers`）。
6. **可达性**：必须提供镜像地址（国内用户为主）。本机已有 gitcode 镜像先例。

## 1. 取证：为什么不能直接搬 WorkBuddy

### 1.1 三层版权链

| 层 | 来源 | 许可事实 | 可用性 |
|---|---|---|---|
| WorkBuddy 客户端本体 | 闭源商业产品 | 无官方开源仓库 | 不可用 |
| 专家市场 manifest | 腾讯云 COS 匿名可读，本机缓存 `~/.workbuddy/app/cache/experts/manifest.json` | **448 位专家，字段里没有任何 `license` / `openSource` 声明**（逐字段实测） | 不可用（保留全部权利） |
| `vbarter/workbuddy-experts` | GitHub 第三方整理，246 位 | `LICENSE` 顶部 `SCOPE NOTICE`：MIT **只覆盖** README / PROMPTS.md / INDEX.md；`NOTICE` 点名腾讯专有部分；README 写「仅供个人学习……禁止批量公开转载或商业再分发」；GitHub API `license.spdx_id = NOASSERTION` | 不可用 |

**"第三方重新授权就与我无关"不成立**：谁分发谁承担，第三方错误贴 MIT 不能替原作者授权。

### 1.2 该仓库的内容其实来自 MIT 上游（字符级实测）

- 对 246 份正文与 `agency-agents` 全量语料做**最长逐字连续段**比对：**138 份命中 ≥1000 字符**（多份顶到 3000 字符采样上限），108 份无重叠。
- 该仓库 `NOTICE` 亦自述 "The bulk of the 246 expert prompts is derived from this MIT project"。
- **结论**：绕开它，直接用上游。它自己也没丢署名（但我们不必经过它）。

## 4. DSH 宿主接口（本机 `@deepseek-ai/dsh = 0.2.0-rc.2`，实测）

### 4.1 斜杠命令 `@deepseek-ai/dsh-commands`

```ts
interface CommandDefinition {
  readonly definitionId?: CommandDefinitionId
  readonly name: string            // 小写、不含斜杠；按名解析（find(agent, name)）
  readonly description: string
  readonly input?: CommandInputDescriptor   // { hint: string, attachments?: boolean }
  readonly recordInput?: boolean
  readonly handler: (invocation: CommandInvocation) => CommandResult | Promise<CommandResult>
}
interface CommandInvocation {
  readonly commandId: CommandId
  readonly agent: Agent            // ← 注意：给的是 agent，不是 sessionId
  readonly rawInput: string        // 命令名之后的全部文字（含分隔空白）
  readonly attachments: readonly (ImageBlock | FileBlock)[]
  readonly signal: AbortSignal
}
```

`CommandRuntime.register()`：**全局定义 + 按 agent 作用域的影子定义**，`list(agent)` 返回 name 排序后的描述符。

### 4.2 输入触发器 `@deepseek-ai/dsh-client-ui-input-trigger`（`@` 通道）

```ts
type TriggerChar = '/' | '@'
interface InputTriggerSource {
  readonly trigger: TriggerChar
  readonly name: string            // 同一 trigger 下唯一；重复注册会 THROW
  readonly order?: number
  readonly showGroupTitle?: boolean
  candidates(session, req: CandidateRequest): Promise<readonly InputTriggerCandidate[]>
  header?(...): readonly InputTriggerCrumb[] | undefined
  onPick(pick: InputTriggerPick): PickOutcome
  matchSpace?/matchEnter?(...): PickOutcome
  warm?(session): void
  lexicon?(session): readonly string[] | undefined
  codec?: ReferenceCodec           // { clipboardText(ref), serialize(ref, signal) }
}
interface InputTriggerCandidate {
  readonly name: string            // 身份：pick 载荷 + 精确匹配键 + 第一搜索键
  readonly label?: string          // 缺省取 name；也是第二搜索键
  readonly description?: string
  readonly section?: string        // 相邻候选的视觉分组
  readonly value?: string          // 源自有 pick 载荷
  readonly drill?: boolean         // Tab / 箭头可就地细化（下钻）
}
interface CandidateRequest {
  readonly query: string           // 触发符到光标之间、**已实时过滤**的文本
  readonly position: 'leading' | 'inline'
  readonly drilled: boolean
  readonly signal: AbortSignal     // 查询变化即作废
}
```

`codec.serialize(ref, signal)` = **模型侧序列化**（决定模型看到什么）；`clipboardText` 只管复制/持久化。

## 5. 被本轮讨论否掉的方向（避免重复论证）

| 曾考虑的方案 | 否掉的理由 |
|---|---|
| 直接搬 `vbarter/workbuddy-experts` | MIT 只覆盖整理工作；正文版权归上游与腾讯；仓库自述禁止商业再分发 |
| 走 npm 包（如从 `@michengai/dsh-agency-agents` 取快照） | 引入第三方依赖且版本由包作者决定；两个正源都没有 npm 形态，已作废 |
| Fork 上游、全量适配后发布自己的仓库 | 从「同步者」变成 785 份文件的分发者；要跟上游变化 + fork 漂移**两处对账**；与「同步而非复制」矛盾 |
| 做「全量同步」功能 | **不该存在**：用户只需几条；全量同步会把名册、token、解析成本一次性拉满 |
| 按专家名注册 `/` 命令（`/workbench-天线测量专家`） | 785 条命令会让 `/` 菜单报废；DSH 的实体选择通道是 `@` |
| 抄 `modelInvocable:false` 省 token | 那是给「几百条随包内置」的场景准备的；按需同步粒度下名册本来就短 |

## 6. 自家代码的既有约束（有行号）

- **persona 解析器是封闭五键**：`src/personas/parse.ts:76` `FRONTMATTER_KEYS = ['name','description','group','mode','emoji']`；`:126-127` 出现其他键 → `unsupported-frontmatter`，**禁用整份文档**（不忽略、不猜测）
  → agency 的 `color` / `vibe` **必须删**；K-Dense 的 `work_mode` → `mode`，`summary` → description，`# AGENTS.md — X` → `# 名称`，`group` 需按目录/`domain` 补
- 长度契约：简介 **160** 字符（超长截断并给 `description-truncated`）、正文 **20000** 字符（超限**禁用不裁剪**）— `src/shared/persona.ts`
- **三级根**：内置 `assets/personas` / 用户 `~/.dsh/workbench/personas` / 外部 `personaExternalDir`（`src/shared/contracts.ts:297`）——外部根是**只读**的，工作台从不写（`src/personas/library.ts:8-10`）
- **同步落点应是用户库**，不是 `assets/`、不是外部根；也**不要**混进 `~/.dsh/skills`（那是 DSH skill 目录）
- **唯一的真改造点**：`personaExternalDir` 目前是**单个 string**，多源需要变成**带稳定 id 的列表**
- 客户端**尚未使用** `ctx.inputTriggers`（`inputTriggers` / `registerSource` 在 `lib/client.js` 中零命中）→ `@` 是净新增能力
- 客户端 `slots` / `layout` / `uiSession` 等可选服务**一律 `ctx.get` 软探测，绝不写进 `inject`**（`src/index.ts:52`、`src/client/runtimeServices.ts:14`）
- host `inject = ['webServer','systemPrompt','tools','commands']`；命令注册点 `lib/index.js:107`，定义体 `:122-129`
- **宿主侧 `src/api/skills.ts` 已在消费 `skills` 服务**（`probeSkills` 软探测 + 归一化），注释明写"技能由 skillport / skills-manager 等 provider 提供" → 注册 provider 这条路在本宿主可行，但工作台目前**只读不注册**

## 7. 已对齐的决策

1. **按需同步单个专家**；不做全量同步；第三方专家不同步就不能用。
2. **分组按源**：源 → 分组 → 角色；每源一个独立转换器，**不 fork**。
3. **转换器不是脚本**：每源一个版本化模块 + fixture 单测，输出我们的格式；上游格式变化要**大声失败**，不能静默丢件。
4. **同步厚度**参考 K-Dense 原生形态；正文落一份、原始打包文件作附件（待 diff 确认后再定）。
5. **附件脚本只读不执行**（工作台不执行附件脚本），UI 必须标注"参考材料，不会执行"。
6. **必须提供镜像地址**（国内用户为主；本机 gitcode 先例）。
7. **需求②（会话中途调用专家）= 子 Agent 叠加**，不换绑（避开"不同绑定 409"与历史消息语义问题）。
8. **命令形态**：`/` 只用一条（或复用 `/workbench`）带自由输入；专家选择走 `@` 候选菜单。
