## 3. 新增工具 `scripts/check-pii.mjs`（入库，非一次性脚本）

发布 skill 第 4 条要求"发版前必须扫私人信息，而且分两个面扫"。本仓库真犯过
（真实 Windows 账号名 + 内网路径被推送，其中 3 处还进了会随 npm 包发布的 `lib/**`），
所以把扫描器**入库**，以后每次发版前跑：

```sh
node scripts/check-pii.mjs          # 两个面都扫（退出码 0 = 干净）
node scripts/check-pii.mjs tracked  # 只扫 GitHub 面
node scripts/check-pii.mjs dist     # 只扫 npm 包内容面（需先 pnpm build）
```

设计要点：

- **面一** = `git ls-files`（GitHub 公开面）；**面二** = `lib/**`（会随包发布，JSDoc 也会进去）；
- 规则里的私人标识**用拼接构造**，工具自身不含字面量（否则自指命中）；
- 规则**故意只查真实仓库路径形态**，不查 `D:\Code\my-repo` 这类给用户看的示例文案 ——
  写宽了会一次报 40+ 处误报，把真发现淹掉（本项目踩过）；
- 合成夹具（脱敏函数的测试值）有豁免，但豁免条件要求值里带 `secret`/`token` 这类**自述词**；
- 命中时退出码 1，并在输出里提示"逐条人工判断，别一键全删"。
