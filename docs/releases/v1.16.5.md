## 0. 范围表（动版本号之前先填，写不出来就别发）

| 列 | 内容 |
|---|---|
| **本版主题** | **工作台样式节点丢失后的自愈**：插件活动期间 `style[data-dsh-personal-workbench-style]` 被移除时，关闭态（或任何状态）的面板会因为计算样式退化成 `position: static; display: block` 而**无样式弹出并覆盖界面**。本版把"样式在被删掉之后还能自己长回来"做进插件生命周期：观察者只在插件 load 期间存活，dispose 时先摘掉自己再断开。 |
| **主线变更** | ① `src/client/index.tsx`：插件 instance 内新建 `styleObserver`（`new MutationObserver`）观察 `document.head` 的 `childList`，未 disposed 时调 `ensureStyle()` 重建样式节点；`cleanup()` **先置 `disposed = true` 再 `styleObserver.disconnect()`**（顺序是判据盯住的点，反了就会在卸载后把样式写回去）；`disposePreviousInstance()` 兜住"上一实例的观察者没断干净"这一路径；首版的模块级 `styleHealArmed` 已移除 —— **自愈能力属于实例，不属于模块**。② 新增 `test/styleRecovery.test.mjs`（97 行 / 7 例）：重复删除后恢复为**单节点**、cleanup 幂等、清理后待处理的变更通知不能再恢复、重新 `apply` 会重新挂观察者、已 disposed 的模块不能恢复旧 CSS、无关的 head 变更不会复制出第二份 CSS、上一实例的清理先于新观察者注册。 |
| **夹带项（1 件）** | **main 的 CI 连续 33 次红的修复**（`05fea07` + `7980493`）。为什么必须同版：CI 自 2026-10-01 run #51 起就红（`test/db.test.mjs` 的一条既有断言），本版合入 PR #10 时**它也是红的**（run #83），不修则本版的发布门禁（`pnpm test` fail 0）给不出绿灯。修的是测试自己，产品代码零改动：① 那条"同链计划项必须被拒"的断言用的是**两条互不相关的顶层叶子**，从 `0d95769`（2026-10-01）引入它的那一刻起就不可能触发（`4751332` 的 ADR0010 只换了期望文案、没换场景）；② `removeTempDir` 在 `finally` 里 `throw`，JS 语义下会**顶替**真正的断言失败 —— 这正是本项目长期把"断言失败"读成"Windows 清理期 `EPERM` 假失败"的原因，也解释了它为什么能红 33 次没人当回事。顺带把 `scripts/release-preflight.mjs` 里登记的那条已知失败欠账**还清并删除**。详见任务资料夹 `docs/tasks/700bd8b2-…/ci-fix.md`（本机资料，未随包、未入库）。 |
| **随本版送达的非编译内容** | `fb2b548`（v1.16.4 发布产物表回填）、本次调研/修复的文档（`docs/tasks/700bd8b2-…/`）按既有规矩**不单独发版**，跟随本版。 |
| **被推迟** | ① **桌面端实例（19387）换到本版**（要重开应用，属用户操作）；② **"样式节点在自然故障中为什么被删除"的根因** —— Issue 作者未捕获自然故障调用栈，本版交付的是**防御性自愈**，不是根因修复；③ 正式库迁移（本版 schema 仍为 19）；④ `docs/releases/v1.16.0~v1.16.4.md` 里"唯一失败 = Windows 清理期 EPERM 假失败，所有断言都跑过了"的**历史表述不回改**，以本版 §8 的口径为准。 |

## 4. 破坏性变更与兼容性

- **无破坏性变更**：无 schema 变更（仍为 **19**）、无字段增删、无 API 形状变化。
- 客户端运行时**多了一个 MutationObserver**（只在插件 load 期间存活，`childList` 观察 `document.head`）。
  卸载/重载路径已由 `cleanup()` 的顺序判据与 4 条生命周期用例守住建。
- 测试侧行为变化（只影响本仓库 CI）：Windows 上临时目录实在删不掉时**不再让该用例失败**，只在输出里留一条
  `console.warn`。这是刻意的取舍 —— **宁可留目录，不可吞断言**。

## 8. 已知问题

- **样式节点在自然故障中"为什么被删除"仍未定位**（Issue #9 作者也未能归因，没有自然故障的调用栈）。
  本版交付的是**防御性自愈**：删掉之后 ~600ms 内回来。若删除方的行为超出"`document.head` 的 childList 变更"
  （例如整个 head 被替换、head 内容被清空、外部持续删除），不在本版的覆盖范围内。
- **历史发布说明的表述与事实不符**：`docs/releases/v1.16.0~v1.16.4.md` 写的
  "唯一失败 = Windows 清理期 EPERM 假失败，所有断言其实都跑过了" —— 实测**不成立**
  （本机那是断言失败被 `finally` 里的清理异常顶替；Linux CI 上则是断言真失败）。
  四篇历史文档按原样保留，**以本版为准**。
- 桌面端实例（19387）需用户自行装盘并重启才会用上本版。
