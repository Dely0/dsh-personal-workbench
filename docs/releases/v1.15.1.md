# v1.15.1 Release Notes

> 主题：**吸收 fork 的成果，并把"任务资料夹"从"按标题"改成"按任务 ID"**
> 验收状态：**已通过本机实测**（用户重启 + 硬刷新后逐条走完；`pnpm test` 240 例全绿）
> 上一个稳定点：`v1.15.0`

## 1. 主题一：任务资料夹规矩（本次最大的一项）

### 旧口径的三个真实毛病

任务没填工作区时，原先按**任务标题**在默认工作区下建文件夹（`<默认工作区>/<标题前 24 字>`）：

1. **改标题 → 文件夹成孤儿**（路径里写死了当时的标题）；
2. **同名任务挤同一文件夹**（两个"周会"共用一个目录）；
3. **标题里的中文/特殊字符直接变成目录名**（Windows 上 `：` 之类还会踩坑）。

顺带还有一个更隐蔽的：**澄清阶段按用户打的那句话建文件夹** ——
等于拿一句自然语言当目录名。

### 新口径

- 文件夹名 = **`<任务ID>-<标题片段>`**（改良版：纯 UUID 人不好认，加标题片段"稳定 + 可读"兼顾）；
  **判定只看 ID 前缀**，所以之后改标题不影响"这是自动路径"这个结论；
- **澄清阶段先预留任务 ID**（客户端 `crypto.randomUUID()`），用它建资料夹并写进提示词，
  确认草稿时复用同一个 id（`workbench_submit_task` 的 `task_id`）——
  于是"资料夹名 ↔ 任务 id"天然一致，那条"澄清资料夹"的特殊分支被删掉；
- **不再为每个任务注册 AI 工作区**：任务一多，宿主的**工作区列表会被任务撑爆**。
  现在会话用**当前工作区**，任务资料夹只在提示词里声明。

### ⚠️ 老路径兼容（照抄 fork 会踩的坑）

fork 的判据只认"末段 == 该任务 ID"。本机真实库里有 **3 条标题型**自动路径
（`D:\DSHWorkspace\工作台任务提醒接入微信（可选增量能力）` 等），在新口径下不以 ID 结尾，
**会被判成"用户手填" → 永远不会随默认根目录迁移**。

所以判据分三类（`classifyTaskWorkspacePath` 是唯一权威，另两个函数由它派生）：

| 类别 | 判据 | 后果 |
|---|---|---|
| `id` | 末段 `=== id`，或（id ≥ 8 字符且）末段以 `<id>-` 开头 | 自动路径，允许改写/迁移 |
| `legacy-title` | 末段 == `folderForText(标题)`，**且**位于默认根目录之下 | 同上（老路径兼容） |
| `manual` | 其余 | **永不触碰**（本机 26+ 条用户手填的真实项目目录） |

测试用**只读导出的本机真实数据**做断言（3 条标题型 + 2 条手填型），不是编的字符串。

## 2. 主题二：快速录入附件（图片 / PDF / DOCX）

- **图片**：走宿主**原生多模态管线**的 `PromptContentPart`（`{type:'image', mediaType, data, name?}`），
  不依赖任何视觉插件；4 种 MIME、最多 10 张、移除时 `revokeObjectURL`；
- **PDF / DOCX**：新端点 `POST /api/workbench/quick-attachments/extract-text` 抽正文，
  最多 4 份、单份 ≤ 5MB、正文截 24000 字符并回 `truncated`；
- **不收的文件必须给可读原因**（`.txt`/`.exe`/超 5MB 都逐条回显），**绝不静默丢弃**
  （本项目有过"5 个子任务凭空少 2 个"的同类事故）；
- **模型收不收图**：宿主只在模型**声明了** `inputModalities` 且不含 `image` 时把图片换成
  一行占位文字（`[image omitted because this model accepts text only…]`）——用户看到的是
  "我传了截图，AI 却说没看到"。所以选中这类模型时**在发送前**给可读中文拒绝。
  能力映射由新端点 `GET /api/workbench/model-modalities` 提供（宿主 `llm` 服务**软探测**）。

### 解压炸弹护栏（**fork 的实现不可照抄**）

fork 的写法有三个错叠加：两处 `inflate` **没传 `maxOutputLength`**；
`uncompressedSize` 是**从 zip 中央目录读出的、攻击者可控**的字段；
`.subarray(0, uncompressedSize)` 发生在**解压之后** —— 内存里已经躺着整份膨胀结果。
请求体上限 5 MiB、deflate 最大压缩比约 1030:1 ⇒ **一个 5 MB 的恶意 .docx 足以打爆主进程**。

本实现三层护栏，缺一不可：**解压前**按声明值拦 → **解压时** `maxOutputLength`
（zlib 在膨胀过程中就停）→ **解压后**复核实际长度。
另外两条同源问题一并改掉：宽松 base64 改为**canonical round-trip 校验**；
PDF 的 `lastIndexOf('<<')` 回扫（O(n²)）改为**单向前进 + 配对括号**扫描。

## 3. 其它新增

- **模型选择器**（快速录入内）：列表与选中都走宿主 `modelDirectories` 的同一个 directory；
  选中值含 **reasoning effort**；不收图的模型在列表里标注「不支持图片输入」。
- **`/workbench` 斜杠命令**：走宿主原生 `ctx.commands.register`（**因此会出现在原生 `/` 菜单里**，
  没有自建 DOM 补全浮层）；执行后 `agent.steer` 一条带澄清指令的用户消息，
  **当前会话直接进入澄清流程**；服务端先按 `<任务ID>-<标题片段>` 建好资料夹再交给 AI。
- **请求围栏合并**：原先四份逐字相同的 `isLoopbackRequest / writeJson / readJsonBody`
  合并成 `src/api/http.ts` 一份，并给所有工作台响应加上
  `cache-control: no-store` 与 `x-content-type-options: nosniff`
  （返回的是用户私有数据，不该被缓存；也不该让浏览器按内容猜 MIME）。
  有源码扫描测试证明"不存在第二处实现"。

## 4. 修复

- **任务没填路径时会话会挂到无关工作区**（真 bug，fork 顺手修了而我们还在）：
  原写法是 `ws.items[0]?.workspaceId` —— **随手取列表里第一个**，最坏情况是
  **另一个任务自动生成的资料夹**，于是本次的文件全落进了别人的任务目录。
  现在按"当前会话 cwd 命中的工作区 → 唯一候选 → **明确拒绝**"来定（纯函数 + 单测），
  **绝不猜**（猜错工作区的代价是"文件悄悄落到别的项目里"）。
- **澄清阶段按用户原话建文件夹**（见上）。
- **PDF 文本抽取的灾难性回溯（本版最严重的一处，由独立审查发现）**：
  `/\[((?:.|\r|\n)*?)\]\s*TJ/g` 在"大量 `[` 却没有 `]`"的输入上是 O(n²)：
  实测输入翻倍耗时 ×4（8k→45ms、16k→171ms、32k→673ms、64k→2770ms），3 MiB 样本 300 秒不返回。
  `extractPdfText` 是**同步**函数、跑在宿主 event loop 上，且客户端在**拖入文档的瞬间**就请求它
  ⇒ **一个 3 KB 的恶意 pdf 足以让整个 dsh web 无响应**（5 MiB 上限与 64 MiB 解码预算都拦不住：
  这不是内存炸弹，是 CPU/事件循环炸弹）。改为单遍线性扫描 + 工作量上限。
- **解压超限会把 zlib 的英文原文甩给用户**（`Cannot create a Buffer larger than 33554432 bytes`）
  → 翻译成中文原因。
- **预分配任务 id 只 `trim()` 不校验**：`../../evil`、`...`、500 字符都能原样落进 `tasks.id`
  （"资料夹名 ↔ 任务 id"这条唯一关联会断裂）；两条草稿用同一个 id 时，
  第二条会拿到 `UNIQUE constraint failed: tasks.id`（英文 SQL 原文）。
  现在白名单校验 + **先读后写**查占用 + 工具侧返回可读中文错误，**当场拒绝、不静默改写**。
- **`/workbench` 命令侧未做 WSL 路径归一化**：WSL 宿主上
  `mkdirSync('D:\DSHWorkspace\x')` 会在当前目录建出一个名叫 `D:\DSHWorkspace` 的**单层目录**，
  任务执行会话随后拿到一个不存在的 `workspace_path`。改为复用既有的 `toNativePath`。

## 5. 破坏性变更

**无接口破坏**，但有两处**行为变更**值得知道：

1. 新任务的资料夹名从"按标题"改成 `<任务ID>-<标题片段>`；
2. 不再为自动资料夹注册 AI 工作区（会话用当前工作区 + 提示词声明资料夹）。
   用户**手填**的工作区行为不变（仍然连过去，永不改写）。

## 6. 依赖与支持边界

| 项 | 要求 | 拿不到时 |
|---|---|---|
| DSH（Web） | **`0.1.5-rc.1`+** | 客户端面板整块不启动（打可读日志，不降级） |
| 宿主服务（`inject`） | `webServer` / `systemPrompt` / `tools` / **`commands`** | 缺 `commands` 则插件 pending —— 它是 `/workbench` 的**前置条件**，且自 `0.1.5-rc.1` 起就有，仍在支持范围内 |
| 客户端服务（`inject`） | `sessions` / `workspaces` / `connection` / `slots` / `layout` | 同上 |
| `modelDirectories`（模型选择器） | 可选增强 | **软探测**：拿不到只是少一个选择器（面板照常启动），发送前的收图提示随之退化为不拦 |
| 宿主 `llm`（模型能力映射） | 可选增强 | 软探测：拿不到则 `/model-modalities` 返回 `available:false` |
| Node.js / pnpm | `^22.19.0` \|\| `>=24.0.0` / `>=11.7.0 <12` | — |

> **关于 `commands` 进 `inject` 的取舍**：它在 `0.1.5-rc.1`（= 本仓最低支持版本）就已提供，
> 属"支持范围内的前置条件"，符合本项目"前置条件进 inject、可选增强软探测"的规矩。
> 而 `modelDirectories` / `llm` 都**没有**进 `inject`：写进去会让没装对应服务的机器上
> **整个插件/面板 pending**，成本不对称（丢整块换一个下拉框）。有测试把这条决策钉住。

## 7. 验收方式

```powershell
node scripts/check-installed-fingerprint.mjs   # 装盘产物 == 当前构建（逐文件 SHA256）
node scripts/check-installed-version.mjs       # 装盘 / profile 声明 / 锁文件 / DB schema 一致
dsh --profile web --dump-config > $null; $LASTEXITCODE   # 0，且无 pending
pnpm typecheck; pnpm test                      # 240 pass / 0 fail（上一版 168）
```

界面逐条（重启 `dsh web` + 浏览器硬刷新后）：

1. 输入框打 `/` → 菜单里有 **workbench**；执行 `/workbench 周五 10:30 接待重要客户`
   → 当前会话进入澄清，且 `D:\DSHWorkspace\` 下出现 `<uuid>-周五 1030 接待重要客户`；
2. 快速录入里加 1 张图 + 选 **deepseek-flash** → 图片进会话，AI 说得出图里内容；
3. 再加 1 张图 + 改选 **deepseek-v4-flash**（未声明 image）→ **可读中文拒绝**，附件保留；
4. 拖入 PDF/DOCX → AI 能引用正文；拖入 `.txt` → 顶部逐条给"只支持…"的原因；
5. 确认草稿后，任务 id == 资料夹名前缀那个 uuid。

> 独立审查（fresh-eyes）另修了 5 条，其中 4 条（PDF 回溯、错误文案、id 校验、WSL 归一化）
> 都被"把 bug 装回去必须变红"的反向验证钉住；`test/quickAttachments.test.mjs` 原本在模块顶层
> 分配 1 GiB 缓冲（并发跑测时的真实内存风险）也一并对齐。

## 8. 已知问题

- `docs/release-checklist.md` 里「`dsh plugin add file:…` 会刷新装盘产物」这句与实测不符：
  **同一路径**下 pnpm 会复用已解包的文件（锁文件 integrity 变了、但 `lib/` 还是旧的）。
  身份必须靠**新路径**（本仓 `dev-install.mjs` 的构建戳命名正是为此）；固定的 `current.tgz`
  只适合回退。已由 `check-installed-fingerprint.mjs` 抓出过一次。
- `scripts/dev-install.mjs --apply` 会删掉自己刚打好的那个包（`-dev-*.tgz` 按**字典序**裁剪，
  新 commit hash 排前面时中招），随后 `dsh plugin add` 指向一个已删除的路径。
  本轮绕开（装 `current.tgz` / 手工 `pnpm pack`），**未修**。
