## 2. 逐条变更

### 2.1 AI 会话工作区双模式（新增）

- 新增 `src/client/components/WorkspacePicker.tsx`，**快速录入 / 新建任务 / 编辑任务三个入口共用一份**：
  1. **已有工作区真下拉** —— 候选 = 宿主已打开的工作区 ∪ 最近手动选择 ∪ 默认工作区，
     按全项目统一的 `recentWorkspaceKey` 口径去重，标注「已打开 / 最近 / 默认」；
  2. **「浏览…」文件夹弹框** —— 复用 `LocalDocModal` 的 `dir` 模式（同一组件、同一份目录浏览骨架，
     **不是**第二份弹窗），支持「选择此文件夹」与「选定当前文件夹」。
- 候选集判定收进 `src/client/workspacePicker.ts`（纯函数，唯一实现）；列目录请求形状收进
  `src/client/localDirBrowser.ts`（原先在 `index.tsx` 里现场拼 `?path=`）。
- 非字符串/空白候选一律丢弃（`String(42)` 会把数字变成候选路径 `'42'` —— 这条由测试当场抓出）。

### 2.2 「今日」与「日历」收敛为同一个日期面板（ADR 0001）

- 新增 `src/client/components/DayPanel.tsx`：**计划 / 已完成 / 报告**三页签 + 计划面板 + 任务树 + 报告卡。
  「今日」= 它的 today 实例（外层多两张卡：统计卡与容量条）；「日历」= 它的周/月容器。
- 任务树口径统一为 **当日到期 ∪ 当日计划项 ∪ 进行中**，**逐条标出来源**（行上的徽标，
  可多来源如「计划 · 进行中」）。判定收在 `src/shared/dailyPlanPolicy.ts`：
  `classifyTaskDay()` 是唯一口径，候选池 `planCandidates()` 与面板树都从它派生。
- 新增 `src/client/dayPanelModel.ts#useDayPanelModel` 作为数据层；`src/client/index.tsx`
  **5743 → 5697 行**（两份视图装配合并成一份 props 对象）。
- ⚠️ **行为变更**：今日页**不再列出全部未完成任务**（旧口径是 `buildTaskTree(openTasks)`）。
  截止在几天后、未排入今天、状态 `todo` 的任务不再出现在今日页 —— 去「任务」页或日历里看。
  同时删掉旧补丁文案「另有 N 个进行中任务未设置截止时间，暂列今天」（该来源已进口径）。

### 2.3 修复：从对话框里打开的自绘弹窗被整块盖住

工作区「浏览…」弹窗从「快速录入 / 新建任务」对话框里打开时**完全点不动**：
真实鼠标点在按钮坐标上，命中的是对话框里的元素。两个原因叠加：

1. `LocalDocModal` 内联在面板里，而对话框基座 `Modal` **portal 到 `document.body`**；
2. `.wb-modal-mask` 的 `z-index` 是 **200**，低于对话框的 `.wb-overlay`（**300**）。

修法：弹窗也 portal 到 body；遮罩抬到 **320**（夹在 `.wb-overlay` 300 与对话框内浮层 329/330 之间）。
`test/panelCss.test.mjs` 新增静态判据把这三个层级关系钉住。

### 2.4 修复：日期面板三页签与下方内容挤在一起（用户实测反馈）

`.wb-segmented[data-day-tabs] { margin-bottom: 10px }`。间距写在**页签**上而不是内容上 ——
三个页签下面跟的东西不同（计划 → 排序行 + 计划面板；已完成 → 列表；报告 → 卡片），
写内容一侧会走出三种间距。静态判据 + 浏览器几何判据（`suites/day-panel.mjs` 量像素差 ≥8）双保险。

### 2.5 构建期类型源对齐 DSH `0.2.0-rc.2`

- 宿主早已是 `0.2.0-rc.2`（桌面端 `app.asar` 内整套 `@deepseek-ai/dsh-*@0.2.0-rc.2` + cordis `4.0.4`），
  而本仓 `devDependencies` 还停在 0.1.x 线，导致**编译时看到的 API 与运行时不一致**。
- 现把**整族**钉到运行时那一线：`dsh-commands` / `dsh-host-webserver` / `dsh-system-prompt` / `dsh-tools`
  = `0.2.0-rc.2`，`dsh-llm` = `^0.2.0-rc.2`，`cordis` = `^4.0.4`，`cordis-plugin-timer` = `1.1.6`。
  ⚠️ 只升 `dsh-llm` 会让开发树自相矛盾（`dsh-session@0.1.x` 仍 import 已被移除的 `CallId`）——
  必须整族一起升。
- **`peerDependencies` 一律不动**：下界仍是 `0.1.5-rc.1` / `0.1.0-rc.6`。对齐类型源 ≠ 放弃老宿主；
  老宿主靠运行时的能力探测活着，不是靠类型。判据 `test/hostTypes.test.mjs`（4 条）同时守住这两面。

**发布产物复核（不是"退出码 0 就算发成功"）**：

1. 从 registry 拉回真 tarball → `Get-FileHash -Algorithm SHA1` = `46d61b7b…`，与 `dist.shasum` **逐字节一致**；
2. 解包核对：包内 `README.md` 190 行（即本版重写后的新版）、`lib/client.js` 在、`package.json` 版本 = `1.16.1`；
3. **用户视角安装**：空目录 + **全新缓存** `npm i @dely0/dsh-personal-workbench`（不指定版本，走 `latest`）
   → `added 42 packages`，装到 `1.16.1`。

> ⚠️ **本次踩坑（已写进 `docs/release-checklist.md` 与团队记忆）**：发布会话里曾把 `git push` 用的
> `HTTPS_PROXY` 带进了发布命令，registry 请求在**传输途中**被掐断一次。npm 的服务端写入是分步的
> （元数据 → tarball → packument/dist-tag 提交），结果留下了一条"元数据在、包体不在"的中间状态：
> `GET /{pkg}/1.16.1` 返回 200，而 `…-1.16.1.tgz` 返回 404，同时 **npm 网页对维护者把这条记录显示成
> "Published"**（极具误导性）。最终由用户在**正确目录**用会话身份重发完成提交（`time.1.16.1 = 16:07:24Z`），
> 其后 tarball 又经历了约 10 分钟的边缘传播延迟才可取。
> **判据顺序**：`tarball 能下载且 sha1 == dist.shasum` ＞ 用户视角 `npm i` 成功 ＞ 网页显示。
