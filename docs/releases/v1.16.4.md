# v1.16.4 Release Notes

> 主题：**「排入今日」在父任务上的语义定案并落地 —— 计划项必须是可执行叶子，父任务排入 = 展开它下面所有未完成叶子**（ADR0010）
> 上一个稳定点：`v1.16.3`
> 版本号 `1.16.4`（`package.json` / tag / npm / GitHub Release 四者一致）。

## 0. 范围表（动版本号之前先填，写不出来就别发）

| 列 | 内容 |
|---|---|
| **本版主题** | **「排入今日」的父子口径**：计划项必须是**可执行叶子**（下面没有未完成子任务的节点）；在**父任务**上点一次「排入今日」= 按树序**展开它下面所有未完成叶子**（各自取自己的预计耗时/默认投入），父任务**自己不是计划项**、不占容量，在「计划」页签里以**分组行**显示「已排 N / 共 M 个子任务 · 合计 X 分钟」。判定只实现一次（`checkPlanTaskSet`），四条写入口共用；**候选池只收可执行叶子**。口径全文见 [`docs/adr/0010-plan-items-are-executable-leaves.md`](../adr/0010-plan-items-are-executable-leaves.md)。 |
| **主线变更** | ① **shared**：新增 `executableLeafIds` / `expandPlanLeaves` / `dayPlacedIds` / `planGroupSummaries`；写入校验第 4 条从「同一父子链不能同时入列」改为「**新增项必须是可执行叶子** + 不得与既有计划项同链（给『先移除它』的可读原因）」；`PlanCandidate` 拆成 `selfPlanned`（自己是计划项，带投入快照）与 `dayPlaced`（该日已安排，含"非叶子任务子树全排完"）；② **服务端**：`addDailyPlanItem` 展开到叶子并回执 `addedTaskIds`；`PUT /plans/:date`（全量保存）**不展开**、非叶子新增整份拒绝；③ **客户端**：一键排入回执回显"展开了哪几条 + 合计分钟"；「计划」页签的分组行（合计标签、不计条数）；「逾期/未排期」页签里的父任务行仍可一键补齐剩余叶子；④ **AI 侧**四处口径统一成「只能排可执行叶子…出现父任务会被整份拒绝」；⑤ 每条判据都配了**反向变异**（叶子判定 / 同级排序 / 子树继承 / 口径扫描）。 |
| **夹带项（1 件）** | **「清除今日计划」不刷新的修复 + 验收链两处套件假红修复**。为什么必须同版：① 前者是用户**同日实测**报的「清除后卡片、计划项、容量与被排任务都还在」——`clearPlan` 在 `DELETE` 之后漏了 `await refresh()`（`todayPlan` 来自 `bootstrap`，只 bump `planRefreshKey` 在今日视图上什么都刷不到），它与本版改的是**同一片写入路径**；② 后两者（`daily-effort` 的坐标点击 / `day-panel` 的折叠计数）是**用户真实深树数据**触发的套件假红，不修则验收链给不出绿灯，属"必须先修才能发"；③ 随附非编译内容（ADR0010/0001/0002 与 CONTEXT 口径、实现计划、`docs/issues/2026-10-05-clear-plan-does-not-refresh.md`）按既有规矩**不单独发版**，跟随本版。 |
| **被推迟** | ① **桌面端实例（19387）**换到本版（需要用户重开应用，属用户操作）；② 给"已在今日计划里的任务"新增子任务的**历史脏数据**路径（仍会拒绝，只在文案上给「先移除它」；不自动清理）；③ 未来日期排期入口；④ 正式库迁移（本版 schema 仍为 19）；⑤ `test/db.test.mjs` 的 Windows 清理期 `EPERM` 假失败（测试脚手架，另开一次改动）。 |

## 1. 来源与致谢

- 本版**无外部代码合入**，全部改动来自用户 2026-10-05 的两条实测反馈（父/子任务排入今日、清除今日计划不刷新）
  与随之定案的口径 [ADR0010](../adr/0010-plan-items-are-executable-leaves.md)。
- 内置角色库与既有署名链**未变动**，见 [`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md)。

## 2. 需求对照

| 原始诉求（2026-10-05 用户实测） | 本版状态 |
|---|---|
| 未排期**父任务**点「排入今日」后，子任务没进今日计划；再想把子任务排进去**会报错** | ✅ 父任务排入 = **展开它下面所有未完成叶子**（树序、各带自己的投入），回执列出展开了哪几条 |
| 未排期**子任务**先排入后，**父任务排不进**（报错） | ✅ 再点父任务只**补齐缺口**，第三次点幂等（`added:false`） |
| 「清除今日计划」后页面不刷新（卡片与被排任务还在） | ✅ `clearPlan` 补 `await refresh()`；判据钉住"四条计划写入口都必须重拉 bootstrap" |
| 计划页签灰行太丑 / 连正常的进行中单任务也被灰 | ✅ 计划页签**关掉灰化**；计数改用「计划树成员」（进行中的单任务照常计入） |

## 4. 破坏性变更与兼容性

- **对外可见的行为变化（1 条）**：AI 排序工具（`workbench_propose_daily_plan`）现在**只能排可执行叶子** ——
  提案里包含父任务（非叶子）会**整份被拒绝**并给出可读原因。此前是"父子链二选一"，现在的规则更窄也更明确。
- `PUT /plans/:date`（全量保存）不再接受**新增**非叶子项；已在计划里的父任务项（历史数据）**原样保留**。
- 数据库 schema **仍为 19**，无迁移、无字段增删；`daily_plans.items_json` 结构不变。
- 内部类型变化：`PlanCandidate.planned` 更名为 `selfPlanned` 并新增 `dayPlaced`（纯内部契约，无外部影响）。

## 5. 依赖边界

- 无新增运行时依赖；`inject` 清单未变（`sessions` / `workspaces` / `connection` / `slots` / `layout`）。

## 8. 已知问题

- `test/db.test.mjs` 在 Windows 上偶发清理期 `EPERM`（临时目录句柄未释放），**所有断言已跑过**；属测试脚手架，另开改动。
- 「计划」页签**不再灰化分组行**（用户 2026-10-05 拍板）；分组行只靠「已排 N / 共 M 个子任务 · 合计 X 分钟」标签区分。
- 给已在计划里的任务**新增第一个子任务**仍会被拒（可读原因：「已在同一天的计划里，请先移除它」）；不自动清理历史项。
