## 2. 本次修掉的四个根因

上一轮失败的原因是「三件事一次全改、判据互相打架」。这次按交接文档的建议**一次只做一件**，
并且每一步都用真实鼠标事件 + 截图验证。过程中发现真正的问题有**四个**（比交接文档列的多两个）：

### 根因 1 · 官方行点了不开面板 → 宿主状态读不到

`ctx.layout` 是宿主的 `LayoutController`，接口里**只有** `selectPanel` / `toggleSidebar` /
`openRightbar` / `closeRightbar` / `beginNavigation` / `dispose` ——
**没有 `subscribe` / `getSnapshot` / `panelInfo`**（读 `dsh-client-ui-layout/lib/client.js:399-439` 核实）。
panelInfo store 被挂成 **root 槽位的全局 hook props**（`ctx.slots.provideRoot({ hooks: { panelInfo } })`），
只有槽位组件读得到 → **唯一可用通道是组件 props 里的 `usePanelInfo(selector)`**。

旧代码偏偏把这个通道**故意删掉**了（`WorkbenchPanelContent` 的注释写着"绝不调用"，
理由是怕 store 不可用时崩掉整个槽位条目）。于是用户点**宿主**的侧栏行时：宿主把
`activePanelId` 设成我们，我们收不到任何通知，`data-open` 始终是 `undefined`
→ 面板不显示，而宿主已经把会话区让位 → **中央一片空白**（截图实证）。

**修法**：`WorkbenchPanelContent` 在顶层无条件是调用 `props.usePanelInfo?.((i) => i.activePanelId)`，
把读数回写到模块级 `hostPanelId`；显示条件改为

```
显示 = 没被别人挤掉 && (宿主状态可读 ? 宿主选中了我们 : 本地兜底)
```

### 根因 2 · 侧栏两行入口 → 同一条判定写了两份，其中一份判据是错的

宿主 `PanelRow` 把注册时的 `label`（= `ENTRY_TITLE`，长文案「打开工作台（任务 / 日历 / …）」）
写进 `textContent` **和** `aria-label`。而 `syncEntryVisibility` 里的判定查的是
`textContent === '工作台'`（`ENTRY_LABEL_TEXT`，短文案）→ **永远不命中** → 我们那行永不隐藏。
（另一份 `officialPanelRowRendered` 是按 aria-label 的，是对的 —— 典型的"同判定写两份"。）

**修法**：判定收敛成一份 `entryContract.hostPanelRowVisible(root)`，
按 `aria-label = ENTRY_TITLE` 查 + 排除带 `ENTRY_ATTR` 的自建行 + 检查真实可见性。

### 根因 3 · 家族互斥彻底失效 → `MutationObserver` 的 `attributeFilter: []` 一个回调都不触发

`siblingActiveFilter()` 返回 `[]`，注释写着"空数组 = 观察全部属性"。**那条注释是错的。**

实测对照（同一页面同时挂四个观察器，只改两个自定义属性）：

| observe 选项 | 回调触发次数 |
|---|---|
| `{ attributes: true, attributeFilter: [] }` | **0** ← 原实现的误解 |
| `{ attributes: true }` | 1 |
| `{ attributes: true, attributeFilter: ['data-probe-x'] }` | 1 |
| `{ attributes: true, attributeFilter: undefined }` | 1 ← 现在的实现 |

后果：**家族互斥观察器 + 入口行高亮观察器双双是死代码** ——
用户现象正是"taskboard 和工作台的入口的点击没有做到互斥（两个都可以同时被选中）"。
探针：`.pwtest/probe-observer-empty-filter.mjs`。已加单测锁死返回值。

### 根因 4 · 官方路径写 `BLOCKED_ATTR` 会让页面**卡死**

现象极具迷惑性：**没有 JS 异常、没有 console 输出**，CDP `Runtime.evaluate` 30 秒不返回，
`Debugger.pause` 只抓到一帧匿名函数（压缩产物读不出归属）。

二分定位（`.pwtest/probe-bisect-hang2.mjs`）：

| 实验 | 结果 |
|---|---|
| 观察器回调改成空操作 | ✅ 存活 |
| 回调里只保留"关掉自己" | ✅ 存活 |
| 回调里只保留 `syncPanelBlocked` | ❌ 卡死 |
| `syncPanelBlocked` 加回 `if (officialConfirmed)` 守卫 | ✅ 存活 |

机制：官方路径下面板显隐由宿主 `activePanelId` 驱动，`BLOCKED_ATTR` 又让 CSS 把同一棵子树
再关一次 → 两套门控反复触发样式/布局重算 → 渲染主线程被占满。
**原代码本来就有这个守卫，是这次改造时去掉的**，属于"修一个坏一个"。

**修法**：`syncPanelBlocked()` 在官方路径下**只清不置**；让位改由
「走 `setOpen(false)` → 通知宿主把 `activePanelId` 归 null」表达。

### 附带修掉的一处判据错误

互斥判据**不能用本地 `open` 变量**：用户点的是**宿主**的行，宿主直接调 `layout.selectPanel(id)`，
我们自己的 `setOpen` 从不被调用 → 本地 `open` 一直是 `false`，而面板明明显示着。
改用 `isDisplayed()`（宿主状态优先、本地兜底），与 `WorkbenchPanelContent` 的显示条件**同源**。

## 3. 交接文档的三处更正（原文会误导后续判断）

1. **「客户端改动浏览器直读磁盘，刷新即生效」不成立。**
   浏览器加载的是 **profile 里 `node_modules` 那份冻结副本**，不是开发树的 `lib/`。
   实测方法：给两份文件各写一个唯一标记，读取 `globalThis.__WB_SERVED_PROBE__` → 读到的是**装盘那份**。
   工具：`.pwtest/which-bundle-is-served.mjs`。
   （本次迭代用"抄进装盘目录 + 刷新"快速验证，最终交付走正式 pack + `dsh plugin add`。）
2. **「装盘 1.14.43 是旧构建」结论反了。** 两份 `client.js` 的字节差异只是压缩器标识符分配不同
   （装盘版把 `dshWorkbench_entryIcon` 内联成短名后整体左移），语义完全相同。
3. **`verify-final-2.mjs` 当时是"恒过"的。** 它的 `check()` 形参是 `(id, name, ok, detail)`，
   而 9 个调用点全部按 `(id, 条件, 说明)` 传参 → `ok` 收到说明字符串（永远真值）→ 9/9 恒过。
   **侧栏明明两行入口，它照样报通过。** 已修正形参顺序，并把判据从 `textContent` 改成 `aria-label`。
   同一形参错位还存在于另外 15 个 `.pwtest/*.mjs`（未逐个修；引用其结论前先确认形参）。

## 6. 用户报告「打开 taskboard 后插件界面遮挡会话区」· 复现、定位与修复（v1.14.46）

### 6.1 机制（读 task-board 的 `board.module.css` 得到，不是猜的）

task-board 的接管只做两件事：

```css
html[data-dsh-taskboard-active]:not([data-dsh-ssh-active]) [data-dsh-taskboard-view] { display: block; }

html[data-dsh-taskboard-active]:not([data-dsh-ssh-active]) [class*='centerCol'] > :not([data-dsh-taskboard-view]) {
  display: none !important;   /* 只作用于 centerCol 的子节点 */
}
```

关键：**它只负责让「会话列里的内容」让位，完全不管 `shell.overlay` 里的东西。**
而工作台的面板挂在 `shell.overlay`（`position:fixed; inset:0; z-index:55`）——
所以只要工作台没让自己让位，那块 fixed 面板就压在会话列上，
用户看到的就是"打开 taskboard 后插件界面遮挡会话区"。

复现脚本：`.pwtest/verify-board-takeover.mjs`（把 task-board 的**真实 CSS 规则**注入页面 +
造出它的视图容器与激活标记，取代"本机 task-board 被关掉"这个限制）。

### 6.2 修掉的最后一个真 bug：两道门互相锁死

上一版把"兄弟面板开着"用在了**两个地方**：

1. 观察器里"兄弟开了就关掉自己"（对的，宿主 `activePanelId` 随之归 null）；
2. **显示条件**里"兄弟开着就不显示"（错，是个死锁）。

死锁链条：

```text
面板被兄弟挤掉（我们关了自己；但真实 task-board 的标记只在它自己关闭时才摘）
  → 显示条件恒假
  → 用户再点入口：宿主的 selectPanel(同一个值) 被 React 判定"无变化"，连重渲染都不发生
  → 面板**永远打不开**
```

**修法**：让位只保留在 ①，显示与否**只信宿主**；一旦宿主选中我们，
就由我们清掉**残留**的兄弟标记（与 task-board 打开时对 ssh 做的事完全一致，
属家族既定约定）。副作用走 `useEffect`（渲染期做副作用会让槽位条目不渲染）。

实测对照（同一页面、只切"兄弟标记在不在"这一个变量）：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 看板接管 → 工作台是否让位 | ✅ 让位 | ✅ 让位 |
| 工作台开着看板 → 再点工作台入口 | ❌ 永远打不开 | ✅ 能打开，且摘掉看板标记 |
| 两个面板矩形是否重叠 | ✅ 不重叠 | ✅ 不重叠 |

### 6.3 本轮排查方法论（比结论更值得复用）

- **别读代码猜，做受控实验**：`.pwtest/probe-bisect-hang2.mjs` 一次只关一块、每块都校验补丁命中；
  `.pwtest/probe-board-attr-ab.mjs` 把"唯一的那个变量"单独拎出来做 A/B。

  `sibling / readable / hostSelected / localOpen` 每一项的值 ——
