## 1. 今日容量：把算法摆到台面上（本版最大的一项）

### 旧口径的三个真实毛病

1. **算法是个黑盒**：`planned` 的计算**内联在一个 4987 行的组件里**，没有纯函数、没有测试，
   `estimatedMinutes ?? 30` 这一个兜底在 4 处复制粘贴。用户看到「已排 0 min」时**无法判断**
   那是"今天真没事"还是"系统把事算丢了"。
2. **逾期完全不参与，界面上也一个字不提**。真库实测（2026-09-17 快照，库 211 条 / 活跃 26 条）：
   当天计入 **0 条 / 0 min**，而同一批数据里躺着 **10 条 / 750 min 的逾期**。
3. **耗时改不了**。编辑弹窗里根本没有"预计耗时"这个字段 —— 只有 AI 工具能写，
   于是"某任务其实要 3 小时"这件事**永远进不了容量读数**（活跃 26 条里 **20 条**没填耗时）。

### 新口径

- 容量算法收成**唯一权威源** `src/client/capacity.ts`（纯函数、`now` 显式入参、不 import React/不碰 DOM），
  `index.tsx` 只剩一个调用点。**传全量任务列表、函数内自己过滤**（调用点先滤一遍就是"同一语义两处算"，
  是本项目最大的 bug 类别）。
- 界面新增 **「⌄ 规则」面板**：七条口径逐字写在界面上（算哪些任务 / 截止时间如何沿任务树继承 /
  今天到期 / 无截止在推进 / **逾期默认不计入** / 没填耗时按多少算 / 汇总口径），
  下面是**逐条账本**（任务 / 优先级 / 分钟 / 来源标记，表尾 `合计 = 已排`），
  逾期任务**单独成区**并给一个**默认关闭**的开关（打开后计入，读数立刻从 0 变 750）。
- **每条任务可自定义「预计耗时（1–1440 分钟）」**（编辑弹窗 + 新建表单），改完**不刷新**就影响「已排」；
  没填的按**可配置的默认耗时**（缺省 30 分钟，设置页可改）计入，账本里逐条标「按默认 N」。
- **全天任务只影响显示与重复锚点，不改变容量计算** —— 这一条同时写在规则面板里
  （"容量问的是投入多少时间，全天只说明什么时候"）。

### 三处刻意与旧实现不同（都有测试钉住，改回去会红）

| # | 差异 | 为什么 |
|---|---|---|
| 1 | `estimatedMinutes: 0` 旧代码**算 0 分钟**，新代码按"没填"走默认 | 旧口径会让容量条**静默少算**一件任务的成本（"0 分钟的任务"其实不存在） |
| 2 | 逾期默认**不计入**（可开关） | 逾期是历史欠账，混进"今天要做的事"会让读数失去意义 |
| 3 | 截止时间是**无法解析的脏串**时，进账本并标出来，但**不计入"逾期 N 条 / M min"** | 它既不是今天也不是逾期；静默丢掉就是"少了一条又没人说" |

### 怎么证明它算对了（不是"我觉得对"）

- **固定数据集可手工复算**：11 条夹具任务的期望值（默认 `planned=420`、开关打开 `1380`、
  默认耗时 60 → `480`）同时出现在**单测 / 真浏览器 harness / 夹具 / 设计文档**四处；
  而夹具期望值是**手算**的，所以另写一套**独立实现**复算 —— 它当场抓出 2 处手算错误
  （`dueTodayCount` 3→**4**：子任务继承父任务截止也算"今天到期"；开关打开时 `p1` 30→**510**：漏了 T5）。
- **等价性对拍**：把旧内联公式复刻成 `legacyPlanned()`，随机 **200 组**快照与新产品函数逐值对拍，
  唯一允许的差异就是上表第 1 条。
- **真浏览器**量的是页面像素与文案（页面上确实显示 420、账本 5 行 4 列、切开关变 1380、收起后高度 126 vs 757）。
- **变异探针 19/19 全红**：其中包括 5 条**接线类**变异（memo 依赖塞回 `now`、payload 丢字段、
  编辑框初值改常量、面板自己存第二份开关、面板自己求和）—— 它们不改纯函数，纯函数测试照样全绿，
  所以必须由源码级断言守住。

## 2. 知识库被会话 AI 自动用起来

- **两层设计**（与团队记忆同构）：①**自动层** —— 会话开始按「任务标题 + 描述」分句检索、
  每回合收尾按你的提问预取，下一回合把命中条目以 `systemPrompt.context` 注入（**在会话里看得见**）；
  ②**主动层** —— 新增 `workbench_search_knowledge` 工具，让模型在"报错时/写码前"**当回合**就能查，
  并可用 `workbench_knowledge_recall_control` 回报"实际用到了哪几条"。
- **打分口径是被实测逼出来的，不要改回老写法**：两轮翻车（第一版 20 字长提问命中 3 条全 1.00，
  阈值与排序同时失效；第二版真实提问只有 0.31，全被挡在门外）。
  定稿 `score = clamp01(weight * min(1, hits/3) * (0.5 + 0.5*coverage))`，**分字段算分**（权重与覆盖率同字段），
  命中判定 `> 0.34`。
- **两档闸门**（让自动层不再"什么都不给"）：过 0.34 给完整块；`0.20 < score ≤ 0.34` 只给一行提示
  （id + 标题 + 相关度，明说"未达注入闸门、仅供参考"，不给摘要）；`≤ 0.20` 什么都不插。
  实测：真实提问"有可见内容"从 1/11 提升到 **10/11**，完整注入数不变（闸门没放松），对照 4/4 未退化。
- **可观测与可关闭**：`knowledge_recall_log` 落库 + 设置页「知识库召回」面板（检索了什么关键词、
  命中哪几条、是否被引用）；全局开关 + 单会话三态（`turn_off` / `turn_on` / `clear`）。
- **修了一个"承诺与能力不一致"的真缺陷**：v1.15.2 首版里 `agent/turn-stopping` 读的是
  `event.data.message`（真实 `data` 就是消息本体）、`currentTurnOf` 读顶层 `event.turn`
  （真实在 `data.turn.turn`）→ query 恒空 → **每回合自动召回从未发生**（线上 `turn` 行 = 0）。
  由一轮空上下文独立审查发现，并补了 7 条第一方探针（修复前全 exit 1 / 修复后全 exit 0）。

## 3. 知识库与点子页改版

- **知识库**：下拉分类改 **Tab 页**，补**关键词搜索（标题 + 正文 + 标签）/ 标签筛选 / 排序（默认更新时间倒序）/
  分页（默认 10，档位 10/20/50/100）**，时间分组**自适应**（条目少的组并回更旧那组，避免"今天 1 / 本周 0"的空壳组头）。
- **点子页**：卡片改 **2 列网格**（保留类型徽标 / 标签 / 多选 ☑ / 归入文件夹），
  **文件夹区完全没动**；修掉两处"看得见点不动"：portal 到 body 的菜单**继承**了面板宿主的
  `pointer-events:none`（→ 容器 `none` + 本体 `auto` 两段式）、`z-index` 低于面板宿主（40 → 60）。
- 标签区收成单行「常用 6 + 更多▾」浮层，修掉**超过 12 个标签就点不到**的静默截断。

## 4. 修复（用户看得见的三条）

- **知识草稿覆盖不再静默**：`workbench_submit_knowledge` 按会话去重，不带 `draft_id` 的重复提交是
  **覆盖**同一份草稿 —— 而以前弹窗长得和"新建"一模一样，用户点「确认入库」时根本不知道前面几次的内容没了。
  现在回执与界面都说清"已更新本会话已有草稿"并**列出被替换的标题**；重复提交**完全相同**的内容也不虚报
  "前一次已被替换"。
- **快速录入的默认工作区不再被上一次执行的任务污染**：根因不是"执行时写坏了存储"，
  而是**同一个状态被两件无关的事共用** —— `openQuickEntry()` 原来从"当前选中的任务"派生默认值，
  而点「AI 执行」之前 `selected` 必然就是那个任务，且面板收起**不卸载 React 树**，于是"执行过任务 A"留下的痕迹
  被当成了默认工作区。现在默认值只由纯函数 `decideQuickWorkspaceDefault`（上次手动选择 → 系统默认 → 空）决定，
  **输入里没有任何任务/选中项**。
- **快速录入的模型选择框被裁掉**：`position:absolute` 挂在弹窗滚动容器（`.wb-dialog-body { overflow:auto }`）里，
  只会朝上开、上方放不下就被裁（**真浏览器实测常见窗口仅 48% 可见**，1000×400 时菜单顶边 -94px 即视口外）。
  改为 portal 到 body + `fixed` + 纯函数 `placePopover()` 摆放（翻转/收敛/保证在视口内）+
  scroll/resize/ResizeObserver 重算 + Esc 只关浮层 + ↑↓ 键盘。
- **「选择文件」出不了 C 盘**：盘符根（`dirname('C:\') === 'C:\'`）把 `parent` 记成 `null`，
  于是「上级」永远灰着。改为根列表哨兵 + 「此电脑」视图枚举盘符（本机实测 C:/D:/E: 可选）。
- 另修：`dev-install.mjs` 的"清理旧开发包"按**文件名字典序**取最旧，跨日期时会把**刚打好的包**删掉
  → `dsh plugin add` ENOENT（现改为结构性排除本次产物 + 按 mtime 排序）。

## 5. 破坏性变更

**无接口破坏。** 两处**行为变更**值得知道：

1. **逾期任务默认不再计入今日容量**（以前也不计入，但现在**你知道了**，而且可以一键打开）；
2. **新增两个设置项**（默认耗时、逾期口径）—— 都存 meta，**不动数据库 schema**，旧版本读不到也不崩。

数据层：`SCHEMA_VERSION` 仍为 **18**（本版未加迁移；v1.15.1 之后加的是 17 知识库召回日志、18 知识 supersede）。

## 7. 验收方式

```powershell
pnpm typecheck                                   # 0
pnpm test                                        # 521 pass / 0 fail（上一版 240）
node scripts/repro/probe-capacity-mutations.mjs  # 19/19 全红
node scripts/repro/verify-capacity-fixed-dataset.mjs   # 完全一致（0 处不符）
node scripts/repro/harness-real-browser.mjs --case all # 51/51
node scripts/check-installed-version.mjs         # 装盘 / profile 声明 / 锁文件 / DB schema 一致
node scripts/check-installed-fingerprint.mjs     # 装盘产物 == 当前构建（逐文件 SHA256）
dsh --profile web --dump-config > $null; $LASTEXITCODE   # 0，且无 pending
```

真机端到端（在**临时任务**上做，结束时取消并归档，绝不动你已有任务）：

```powershell
node scripts/repro/repro-task-estimate.mjs --token <token>
# 详情行不刷新即显示新耗时；「已排」增量 = 新值 − 账本里旧值；F5 后仍是新值；
# 重开弹窗回显新值；库里一致；非法值（99999）被就地阻止（弹窗不关、有红字、库里值不变）
```

界面逐条（重启 `dsh web` + 浏览器硬刷新后）：

1. 今日页「今日容量」→ 点「⌄ 规则」→ 七条口径 + 逐条账本（表尾合计 = 已排）+ 逾期区 + 开关；
2. 打开「把逾期任务计入今日容量」→「已排」立刻变大；回设置页确认那个开关也是开的（两处写同一个设置）；
3. 随便挑一条任务 → 编辑 → 填「耗时（分钟）」90 → 保存 → **不刷新**看「已排」变化 → F5 后仍 90；
4. 填 0 / 2000 / 留空 → 前两者**行内红字拒绝且不发请求**，留空 = 按默认耗时；
5. 设置页 →「今日容量」：改默认耗时 → 账本与规则文案里的"默认 N"跟着变；
6. 知识库：分类 Tab / 搜索正文 / 标签 chip / 排序 / 翻页；点子页 2 列卡片 + 「归入文件夹」菜单**能点到**；
7. 让 AI 提交两次知识草稿 → 第二次的弹窗要**在点确认之前**就说清"这是替换"并列出被替换的标题。

## 8. 已知问题

- **真机交互验收（第 3 层）由用户完成**：本版所有界面断言止于"真浏览器 + 真 CSS 渲染"，
  点击/输入后的状态变化需要宿主重启后手点（脚本已尽量自动化，但 React 状态在静态渲染下点不动）。
- `.pwtest/` 里有一批"架构变更前"写的脚本（约 80 个长期迭代产物），跑起来会失败但那是**假失败**
  （断言的是已删除的 DOM 降级腿与家族互斥），`verify-acceptance.mjs` 里示范了正确做法。
- 容量口径延续两条既有语义**未改**：① 继承截止时间**不看祖先状态**（已取消父任务下的子任务仍继承其过期 due，
  即"幽灵逾期"）；
  ② 父子同时未完成时**各计一份**（账本给同链标记但不去重）。两者都写进设计文档与规则面板。
