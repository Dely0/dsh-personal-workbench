## 1. 快速录入：模型选择框被遮挡（① / P1）

### 根因（真浏览器实测，不是猜的）

现象记录日期是 2026-09-15 晚。根因**不是** z-index / 层叠上下文，而是**裁剪**：

`.wb-model-menu` 是 `position:absolute; left:0; bottom:calc(100% + 4px)`，挂在触发按钮的
`position:relative` 包装盒里，而盒子在 `.wb-dialog-body { overflow:auto }` **里面**。
于是浮层**只会朝上开**、不看可用空间（按钮上方仅约 130px，菜单内容 262–360px），多出来的部分被滚动口裁掉。

### 修法

- portal 到 `document.body` + `position:fixed`；
- 新增**纯函数** `src/client/popoverPlacement.ts#placePopover()`：上方放不下就翻转、
  上下都放不下就**高度收敛到可用值**、保证盒子永远在视口内（并守非有限输入）；
- `scroll`（捕获阶段）+ `resize` + **`ResizeObserver`** 重算（模型目录异步加载后菜单会长高）；
- 关闭统一走 `closePicker()` **归还焦点**；`Esc` 只关浮层；`↑↓` 移动焦点。

### 证据

- 真浏览器（CDP 驱动 Edge 量 `getBoundingClientRect`）：修前可见比例 **48% / 48% / 48% / 31%**，
  `1000×400` 且弹窗滚动过时菜单顶边 **-94px**（画到视口外）、第一条选项始终不可见；
  **修后 100% / 100% / 100% / 100%**。截图见 `_local-archive/model-picker-occlusion/`。
- 空上下文独立复审又修了 5 条，其中两条是真 bug：
  ① `placePopover` 的"盒子永远在视口内"曾是**假保证**（高度只按锚点那一侧空间收敛，
  锚点在视口外时下沿越出 53px，而弹窗锁了 body 滚动够不着）→ 加**视口上限**；
  ② 方向键打开浮层时焦点落在仍 `visibility:hidden` 的菜单上（**隐藏元素不可聚焦**）→ 静默失效，
  改为等 `placement` 生效后再聚焦。
  另修三处证据效力问题：`Escape` 扫描断言恒真（扫整份文件而非组件函数体）、
  复现脚本对源码不敏感（撤掉修复仍全绿 → 把"接线真的在源码里"做成**证据前提**）、
  CSS 模式的历史基线只覆盖 6 条声明（改为从历史提交整条取回）。

## 2. 快速录入：默认工作区被上一次执行的任务污染（② / P1）

### 根因（不是"执行时写坏了存储"，而是同一个状态被两件无关的事共用）

`openQuickEntry()` 原来写的是 `selected?.task.effectiveWorkspacePath ?? ''` ——
**从"当前选中的任务"派生快速录入的默认工作区**。而"执行任务"留下的痕迹恰好就是它：

1. 「AI 执行」按钮只出现在任务详情里 → 点它之前 `selected` 必然 = 被执行的任务 A；
2. `startAISession` 结尾的 `closePanel()` 只是 `setOpen(false)`，面板显隐走 CSS 的
   `.wb-panel-host[data-open]`，**React 树从不卸载** → `selected` 原样留着；
3. 用户重开面板点「快速录入」→ 默认值 = A 的工作区 X。

**确认过没有"执行 → 写全局默认"的隐式副作用**：`ai_default_workspace` 只在
`POST /api/workbench/settings` 带 `defaultWorkspace` 时写。

第二条腿（自激污染）：`rememberQuickWorkspace` 原来**无条件**记，而该列表同时是下一次的
默认值来源 ⇒ 自动预填的值会被记成"用户手动选的"。

### 修法

- 新纯函数 `src/client/quickWorkspaceDefault.ts#decideQuickWorkspaceDefault({recent, defaultWorkspace, isWsl})`：
  判据只有「上次手动选择 > 系统默认 > 未设置」，**输入里没有任何任务/选中项**；
- `shouldRememberQuickWorkspace(touched, path)`：**只有用户动过输入框**才写最近列表；
- 「建任务资料夹」默认勾选口径统一为 `quickFollowFolderDefault(path, autoCreateTypeFolders)`
  —— **只看全局开关与有没有目标目录**，不按路径来源分叉
  （按来源分叉会**静默**丢掉 v1.15.1 的任务资料夹保证）；
- 新增「不再记住这个目录」出口：`POST /settings {quickWorkspaceRecent}` 由**合并**改**整表替换**
  （合并语义下"删除"不可能，用户改回系统默认就成了死路），归一化/置顶/删除的唯一实现在
  `src/shared/quickWorkspaceRecent.ts`（前后端共用）。

### 证据（真机修前 / 修后对照）

- **修前**：预填 = 任务 A 的工作区 X，提示写着「继承自父任务「工作台插件 v1.15.2 版本优化」」；
- **修后**：同一脚本 `--expect stable` 在**两个不同任务**上各跑一次，预填恒为同一个稳定值
  （= `recent[0]`，提示「上次手动选择」）—— **与最近执行/查看过哪个任务无关**。
- 第二轮复审又收口了并发残留：`forget` 改为**先现读服务端当前列表**再算整表；
  「不再记住」按钮的渲染条件与 `onClick` 补了断言。

## 3. 时间与容量规则透明化（③ / P2）—— 本版最大的一项

### 旧口径的三个真实毛病

1. **算法是个黑盒**：`planned` 的计算**内联在一个 4987 行的组件里**，没有纯函数、没有测试，
   `estimatedMinutes ?? 30` 这个兜底在 4 处复制粘贴。用户看到「已排 0 min」时**无法判断**
   那是"今天真没事"还是"系统把事算丢了"。
2. **逾期完全不参与，界面上也一个字不提**。真库实测（2026-09-17 快照，库 211 条 / 活跃 26 条）：
   当天计入 **0 条 / 0 min**，而同一批数据里躺着 **10 条 / 750 min 的逾期**。
3. **耗时改不了**：编辑弹窗里根本没有"预计耗时"这个字段，只有 AI 工具能写 ——
   于是"某任务其实要 3 小时"永远进不了容量读数（活跃 26 条里 **20 条**没填耗时）。

### 新口径

- 容量算法收成**唯一权威源** `src/client/capacity.ts`（纯函数、`now` 显式入参、不 import React / 不碰 DOM），
  `index.tsx` 只剩一个调用点；**传全量任务列表、函数内自己过滤**（调用点先滤一遍就是
  "同一语义两处算"，是本项目最大的 bug 类别）；
- 界面新增 **「⌄ 规则」面板**：七条口径逐字写在界面上，下面是**逐条账本**
  （任务 / 优先级 / 分钟 / 来源标记，表尾 `合计 = 已排`），逾期任务**单独成区**并给一个**默认关闭**的开关；
- **每条任务可自定义「预计耗时（1–1440 分钟）」**（编辑弹窗 + 新建表单），改完**不刷新**就影响「已排」；
  没填的按**可配置的默认耗时**（缺省 30 分钟，设置页可改）计入，账本里逐条标「按默认 N」；
- **全天任务只影响显示与重复锚点，不改变容量计算**（这一条同时写在规则面板里）。

### 三处刻意与旧实现不同（都有测试钉住，改回去会红）

| # | 差异 | 为什么 |
|---|---|---|
| 1 | `estimatedMinutes: 0` 旧代码**算 0 分钟**，新代码按"没填"走默认 | 旧口径会让容量条**静默少算**一件任务的成本 |
| 2 | 逾期默认**不计入**（可开关） | 逾期是历史欠账，混进"今天要做的事"会让读数失去意义 |
| 3 | 截止时间是**无法解析的脏串**时进账本并标出来，但**不计入"逾期 N 条 / M min"** | 它既不是今天也不是逾期；静默丢掉就是"少了一条又没人说" |

### 怎么证明它算对了

- **固定数据集可手工复算**：11 条夹具任务的期望值（默认 `planned=420`、开关打开 `1380`、
  默认耗时 60 → `480`）同时出现在**单测 / 真浏览器 harness / 夹具 / 设计文档**四处；
  而期望值是**手算**的，所以另写一套**独立实现**复算 —— 它当场抓出 2 处手算错误
  （`dueTodayCount` 3→**4**；开关打开时 `p1` 30→**510**）。
- **等价性对拍**：把旧内联公式复刻成 `legacyPlanned()`，随机 **200 组**快照与新产品函数逐值对拍。
- **变异探针 19/19 全红**，含 5 条**接线类**变异（memo 依赖塞回 `now`、payload 丢字段、
  编辑框初值改常量、面板自己存第二份开关、面板自己求和）—— 它们不改纯函数、纯函数测试照样全绿，
  必须由源码级断言守住。
- **真机端到端 8/8**：在**临时任务**上验证（结束时取消并归档，绝不动用户已有任务）——
  详情行不刷新即显示新耗时、`F5` 后仍是、重开弹窗回显、库里一致、非法值被就地阻止。

> 过程中真机脚本还逮到一个**产品缺陷**：装盘完成、宿主还没重启的窗口期里，
> 宿主跑旧服务端代码、`GET /settings` 不带 `defaultEstimateMinutes`，
> 界面显示成「预计耗时：默认 **undefined** 分钟」→ 新增 `withSettingsFallback()`
> （只补缺失键、用 `??` 不用 `||`）。

## 5. 知识库被会话 AI 自动调用（⑤ / P1）

- **两层设计**（与团队记忆同构）：①**自动层** —— 会话开始按「任务标题 + 描述」分句检索、
  每回合收尾按你的提问预取，下一回合把命中条目以 `systemPrompt.context` 注入（**在会话里看得见**）；
  ②**主动层** —— 新增 `workbench_search_knowledge` 工具，让模型在"报错时 / 写码前"**当回合**就能查，
  并可用 `workbench_knowledge_recall_control` 回报"实际用到了哪几条"。
- **检索范围**：优先本任务 / 本任务树，再扩到全局知识库（与父任务要求一致）。
- **打分口径是被实测逼出来的，不要改回老写法**：两轮翻车（第一版 20 字长提问命中 3 条全 1.00，
  阈值与排序同时失效；第二版真实提问只有 0.31，全被挡在门外）。定稿
  `score = clamp01(weight * min(1, hits/3) * (0.5 + 0.5*coverage))`，**分字段算分**，命中判定 `> 0.34`。
- **两档闸门**（让自动层不再"什么都不给"）：过 0.34 给完整块；`0.20 < score ≤ 0.34` 只给**一行提示**
  （id + 标题 + 相关度，明说"未达注入闸门、仅供参考"，不给摘要）；`≤ 0.20` 什么都不插。
  实测真实提问"有可见内容"从 1/11 提升到 **10/11**，完整注入数不变（闸门没放松），对照 4/4 未退化。
- **可观测与可关闭**：`knowledge_recall_log` 落库 + 设置页「知识库召回」面板
  （检索了什么关键词、命中哪几条、**是否被引用**）；全局开关 + 单会话三态
  （`turn_off` / `turn_on` / `clear`）。关闭后不再检索也不注入，但**主动检索仍可用**。
- **修了一个"承诺与能力不一致"的真缺陷**：首版里 `agent/turn-stopping` 读的是 `event.data.message`
  （真实 `data` 就是消息本体）、`currentTurnOf` 读顶层 `event.turn`（真实在 `data.turn.turn`）
  → query 恒空 → **每回合自动召回从未发生**（线上 `turn` 行 = 0）。由一轮空上下文独立审查发现，
  并补了 7 条第一方探针（修复前全 exit 1 / 修复后全 exit 0）。

## 6. 知识草稿静默覆盖不再静默（同期独立任务 `f4a3430f`）

`workbench_submit_knowledge` 按会话去重，不带 `draft_id` 的重复提交是**覆盖**同一份草稿 ——
而以前弹窗长得和"新建"一模一样，用户点「确认入库」时根本不知道前面几次的内容没了。
最刺痛的场景：一个会话里分多次沉淀多条独立主题 → 每次都"成功" → 最后确认一次 →
**入库存的是最后一次**，前面几次全部白干且**无法发现**。

**修法（本版范围：让覆盖可见 + 文字说明；不改去重架构）**：

- 回执与界面都说清"**已更新本会话已有草稿**"并**列出被替换的标题**；
- 重复提交**完全相同**的内容也不虚报"前一次已被替换"（`planKnowledgeDraftWrite` 的 `unchanged` 模式）；
- 工具说明补上"一个会话只产生 1 条草稿；要在同一会话产出多条，走 `POST /api/workbench/drafts`"。

**明确不做**（与任务描述一致）：不改按会话去重的架构（那是**有意设计**，且有官方绕行路由）；
不做"一次提交多个条目"（草稿内列表化）。

**无接口破坏。** 三处行为变更值得知道：

1. **逾期任务默认不计入今日容量**（以前也不计入，但现在你知道了，而且可以一键打开）；
2. **新增两个设置项**（默认耗时、逾期口径）—— 都存 meta，**不动数据库 schema**，旧版本读不到也不崩；
3. `POST /settings {quickWorkspaceRecent}` 由**合并**改**整表替换**（为支持"不再记住这个目录"）；
   另有一处刻意行为变化：默认值来自"上次手动选择的目录"时，「在该工作区下建任务资料夹」**默认不勾**
   （因为那个目录本身就是用户选的目标），来自系统默认工作区时仍按 `autoCreateTypeFolders` 自动勾。

数据层：`SCHEMA_VERSION` 由 **15** 升到 **18**（本版带迁移 **16** 类型颜色回填、**17** 知识库召回日志、
**18** 知识 supersede）。**schema 只单向前进** —— 回退插件前先确认目标版本能读 schema 18。

```powershell
# ① 模型浮层 —— 真浏览器量可见比例（修前 48% → 修后 100%）

```

界面逐条（重启 `dsh web` + 浏览器硬刷新后）：

1. **①** 弹窗里展开模型选择器 → 常见窗口尺寸下**完整可见、可展开、可选**；弹窗滚动与聚焦时不遮挡；
   `↑↓` 可选、`Esc` 只关浮层、关闭后焦点回到触发按钮；
2. **②** 执行任务 A（工作区 X）→ 再打开快速录入 → 默认工作区**不是** X；手工选定后多次执行其他任务不变；
   点「不再记住这个目录」能真的删掉；
3. **③** 今日页「今日容量」→ 点「⌄ 规则」→ 七条口径 + 逐条账本 + 逾期区 + 开关；
   打开「把逾期任务计入今日容量」→「已排」立刻变大；随便挑一条任务改「耗时」→ **不刷新**看变化 →
   `F5` 后仍在；填 0 / 2000 / 留空 → 前两者行内红字拒绝且不发请求；
4. **④** 知识库：分类 Tab / 搜索正文 / 标签 chip / 排序 / 翻页；任务页：类型 Tab（Ctrl+点多选）、
   状态与优先级下拉仍在；点子页 2 列卡片 + 「归入文件夹」菜单**能点到**；
   设置页「字典管理」里有「知识库类型」；弹窗里「此电脑」能切到 E 盘；
5. **⑤** 让 AI 提交两次知识草稿 → 第二次的弹窗要**在点确认之前**就说清"这是替换"并列出被替换的标题；
   设置页「知识库召回」面板能看到检索了什么、命中哪几条、是否被引用。
