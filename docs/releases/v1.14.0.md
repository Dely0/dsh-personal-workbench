## v1.14.1 修复清单（1.14.0 本机验收发现的 4 个问题）

用户验收 1.14.0 时报了 4 项，逐条给了截图。4 项全部确认为真实缺陷（不是"设计如此"），
根因与修法如下。

### ① 点会话标题栏「工作台」→ 整个会话区变空白，且切会话/点侧栏都回不来（严重）

**根因（两个缺陷叠加）**：

1. `officialSlotDecision()` 用 `entriesOfSlot` 探测槽位时**脱绑调用**（`candidate.entriesOfSlot(...)`）。
   宿主服务的方法依赖实例字段，脱绑会抛异常 → 被当成"宿主没有 `sidebar.panellist`"
   → 于是走了 DOM 腿，**官方入口从未注册**。
   修法：所有宿主服务方法一律 `.call(service, ...)` 绑回；并补单测锁这条。
2. `setOpen()` 里 **先设 `open = true` 再调用 `layout.selectPanel(id)`**，
   而 `selectPanel` 对未注册的面板**会抛错**（宿主源码：`main panel "x" is not registered`）。
   异常被 catch 成一条 console.warn，但 `open` 已经是 true → CSS 门控生效、
   会话列被 `display:none !important` 藏掉，而覆盖层面板因为"走官方路径"没渲染 → **整片空白**。

**修法（不再只靠"探测到的"）**：引入**自愈判定**。

- `layout.selectPanel` 抛错 → 立刻 `fallbackToDomLeg()` 并**递归重试** `setOpen`，
  改走 DOM 腿（那里 `selectPanel` 不参与），绝不留空白；
- 新增 `officialRegistrationComplete()` / `officialPanelRowRendered()` / `officialPathConfirmed()`：
  **注册表（入口 + main 的 key）与 DOM（宿主真的画出了那一行）两侧都有证据**才算确认；
- 启动后 4 秒复核窗口内（DOM 观察 + 3 个定时点 + 收口点）任一不成立 → 撤销官方注册、
  摘掉 `OFFICIAL_ATTR`、切回 DOM 腿；
- DOM 腿的入口行与覆盖层**始终就绪**（官方确认可用时才隐藏入口行），
  最坏情况是"看起来像迁移前"，而不是"什么都没有"。

### ② 草稿弹框出现时背景渐黑、画面闪烁，点「暂存」要连点 5-8 次

**根因**：`WorkbenchApp` 被**挂载了两份** —— DOM 腿的覆盖层一份、官方 `main` 容器一份。
两个实例各自每 5 秒轮询同一个接口、各自维护 `pendingDraft` 状态、各自渲染一个 Modal，
于是弹框互相盖、点击落到被覆盖的那个实例上（要点多次才能命中）。

**修法**：同一条 CSS 门控（`OFFICIAL_ATTR`）保证**同一时刻只有一路渲染 App**：
- 官方确认可用 → 只在 `main` 容器里渲染；
- 否则 → 只在覆盖层渲染。
`mountPanelContent()` 与 `mountOverlayContent()` 互斥，且各带"已挂载"标记，不可能双开。

### ③ 快速录入弹框的提示文字被上方输入框遮挡

**根因**：`.wb-hint` 只有 `.wb-settings-pane .wb-hint` 这一条作用域样式，
弹框里的 `.wb-hint` **完全没有样式**（字号继承、行高默认、上下无间距），
紧贴着一个行内 `<input>` 渲染就被压住了。另外勾选项塞在 `<label class="wb-hint">` 里，
与 `.wb-field` 的列布局互相打架。

**修法**：补全局 `.wb-hint` 基线（字号 12px / 行高 1.6 / `margin: 6px 0 0`）；
字段名右侧说明改用 `.wb-field-note`（`inline-flex` + 居中）；
行内勾选项改用 `.wb-inline-check`（`flex` + `align-items:flex-start` + 独立行距）。

### ④ 非法 `type_code` 拦截失败

**确认是 BUG（不是设计如此），而且比"没拦截"更隐蔽**：
`workbench_submit_task` 的顶层 `type_code` 走的是 `normalizeCode(..., 'personal', ...)` ——
字典里查不到就**静默回退成 `personal`**，工具照样返回"草稿已保存"。
实测传 `not_a_type` / `999` / `CODE_IMPL` 都能落成草稿，类型被悄悄改掉
（用户以为建的是"培训学习"，实际是"个人生活"）。

这与工具描述里"封闭枚举，不要自造"自相矛盾；而**同一文件里子任务的 `type_code`
是严格校验的**（v1.14.0 那条静默丢件修复）—— 同一个参数在两处口径不一致，属于实现疏漏。

**修法**：
- 新增 `strictTypeCode()`：显式给值时必须命中字典启用项或别名表，否则**当场报错并列出合法枚举**
  （缺失/空串才允许用默认值）；错误以 `return '错误：…'` 形式返回，与其它校验一致；
- 回执里**回显最终落库的字段**（`type=… priority=… status=… ai_policy=…`），
  让调用方一眼看出自己给的值有没有被改动 —— 静默改写是用户最难发现的一类偏差；
- 原测试锁的正是旧行为（"未知 code 应回退不报错"），按新契约**反转**为断言拒绝。

`priority_code` / `ai_policy_code` 仍保留宽松归一化（有天然默认值，语义损失小），
但因为回执回显了最终值，被改写时调用方可自查。

### 验证

- `pnpm typecheck` 0 错误；`pnpm test` **129 pass / 0 fail**（126 → +3 项自愈判定回归）。
- 新增回归：注册表/DOM 两侧证据判定、脱绑调用的服务方法、容器二选一的 CSS 契约。

## v1.14.2 ~ v1.14.4 修复清单（第二轮验收发现的 3 个问题）

用户复验 1.14.1 后仍报 3 项，并附了控制台截图（`draft is already abandoned` 连发 5 次
+ 页面一次比一次黑）。三项全部确认为真实缺陷，而且**三项同源**：都是"实例/状态没收干净"。

### ① 任务草稿右上角关闭按钮"没有逻辑"，关掉 5 秒后又弹出

**根因（两层，都真）**：

1. `act()` **只在成功时** `onDone()`，失败时抛出的 promise 连 `catch` 都没有
   （控制台里一条条 `Uncaught (in promise) Error: draft is already abandoned`）。
   用户连点 X 会打出多个 abandon 请求，第一个成功、其余全部 400 → 失败路径不关弹框。
2. 右上角 X / Esc / 点遮罩走的是 `Modal` 的 `onClose`，而我当时只做了
   `setPendingDraft(null)` —— **5 秒轮询**（独立数据源）立刻把同一份 pending 草稿
   又设回 state，于是"关掉又弹出来"。

**修法**：
- `act()` 无论成功失败都收口，并区分两类失败：草稿已不是 pending（`already abandoned|confirmed`）
  → 视为"目标已达成"，静默收掉；其它错误 → 提示 + 收掉（留一个点不动的弹框更糟）；
- 新增 `dismissedDraftIdsRef`（已处理草稿 id 集合）与 `onDismissed` / `onClose` 两个回调：
  **关闭与确认都登记 id**，5 秒轮询结果里命中该集合的直接忽略（`deferredDrafts` 同样过滤）。

### ② 「回到录入会话」点击无反应

**根因**：`openSession()` 先 `closePanel()` 再 `sessions.open(id)`。官方槽位路径下
`closePanel()` → `layout.selectPanel(null)` 会**同步卸载**本插件面板所在的 React 树，
之后的 `sessions.open()` 落在已被拆掉的组件上 —— 表现就是完全没动静。

**修法**：改成**先开会话、再关面板**；并且每一步独立 `try/catch`，
跳转失败也照样把横幅收掉（并登记 id），失败时用 toast 告知，不再"静默无反应"。

### ③ 提交草稿后背景慢慢变黑 + 明显刷新感

**根因**：**多个 `WorkbenchApp` 实例同时活着**。每个实例各自每 5 秒轮询、
各自渲染一个「待确认草稿」Modal。而每个 Modal 自带
`position:fixed; background:rgba(0,0,0,.52)` 的遮罩 —— 三层叠起来就是用户看到的
"一次比一次黑"（0.52 → 0.77 → 0.89）；点击落在最上层那个实例上，
所以"暂存要点 5-8 次"。

实例为什么会残留：cordis 在重载/HMR 时会**再次执行 `apply()`**，而上一版把 React root
建在 `apply()` 的外部作用域且从不卸载 —— 旧实例的轮询与 Modal 一直活着。
控制台里的 `Error: cannot get required service "sessions" in inactive context`
（19 条 error 里绝大多数）就是这些**已卸载实例**在访问宿主服务。

**修法（三层防护）**：
1. **单实例守卫**：模块级 `activeDisposer`；每次 `apply()` 开头先
   `disposePreviousInstance()` 主动拆掉上一轮（断观察器、卸载两条路径的 React root、摘属性），
   清理函数幂等且**无条件** `unmount()` 两个 root；
2. **死上下文防护**：新增 `safeService(runtime, name)`，所有宿主服务（含"必需"的
   `sessions` / `workspaces` / `connection`）一律经它读取，拿不到就返回 `undefined`
   让调用点降级 —— **绝不让旧实例的残留回调把错误抛到用户控制台**；
3. **卸载后停副作用**：模块级 `instanceAlive` 标记，所有 `await` 之后的分支先检查它，
   不活着就直接 return（不再 setState、不再动宿主服务）。

### 验证方式（可复现，零依赖）

新增两个 CDP 脚本（Node 24 自带 WebSocket，**不需要 browser-use / Playwright**）：

```sh

```

### ⚠️ 本次踩到并已固化的坑：同版本号 tarball 会被 pnpm 复用

`pnpm build && pnpm pack && dsh plugin add <同名同版本 tgz>` 之后，
profile 的 `node_modules` 里**仍是旧代码**（pnpm store 按包名+版本号内容寻址，
`--force` 也无效；Windows 解包保留 mtime，所以看时间戳判断不出来）。
我因此白验了两轮 —— "修完还是老行为"，其实是**跑的根本不是新包**。

固化措施：新增 `scripts/check-installed-fingerprint.mjs`，**逐文件 SHA256 比对**
开发树 `lib/` 与 profile `node_modules`，并核对版本号。规则：
**改代码后必须换版本号**，装完先跑指纹校验、再验功能。
（`scripts/check-installed-version.mjs` 只看版本号声明，管不住这件事。）
