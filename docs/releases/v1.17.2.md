## 1. 来源与致谢

- **Issue [#19](https://github.com/Dely0/dsh-personal-workbench/issues/19) / PR [#20](https://github.com/Dely0/dsh-personal-workbench/pull/20)**：由 [@SnowNight777](https://github.com/SnowNight777) 报告（2026-10-27）并亲自修复（2026-10-29）。报告自带两条根因与机制（`retain` 之后 scope 才物化；cordis traceable 服务把服务实例 `ctx` 影射成调用方 ctx，于是宿主里那句 `new ModelDirectory(this.ctx.remote.session, …)` 要求调用方 inject 过 `remote.session`），并明确「不能把 `dsh-client-ui-model-selection` 写进 inject，那会让没装它的机器整块面板 pending」。PR 逐条对上根因，并在 DSH **0.2.1-rc.3 桌面端**实测：重载插件后模型菜单能列出模型、选模型点开始不再报 inject 错。
- **Issue [#17](https://github.com/Dely0/dsh-personal-workbench/issues/17)**：由 [@WUWAN01](https://github.com/WUWAN01) 报告（2026-10-24，正文为 `bug.md` 附件），给出 DOM 结构、`.wb-modal-mask` 的 CSS 位置、`task_sessions` 0 行的证据与具体修补建议（`max-height` / `overflow-y` / sticky 底栏），并指出 `lib/client/styles.js` 运行时**并未被加载**、真正生效的是打进 `client.js` 的那份副本。PR [#21](https://github.com/Dely0/dsh-personal-workbench/pull/21) 由维护者按该报告与建议实现，并补上「缺一条规则就红」的回归判据。
- **PR [#18](https://github.com/Dely0/dsh-personal-workbench/pull/18)**（i18n 深度翻译二轮）：[@Chewbacca96](https://github.com/Chewbacca96)，属 issue [#12](https://github.com/Dely0/dsh-personal-workbench/issues/12) 的后续范围。
- 内置角色库与第三方许可链**未变动**（`THIRD_PARTY_NOTICES.md` 无需修改）。

## 2. 需求对照

### issue #19：模型选择器一个模型都列不出来

| 诉求（issue #19） | 本版状态 |
|---|---|
| 工作台面板里点模型选择器能列出模型，不再报 `ui-model-selection: session "…" resolved no scope` | ✅ 取目录前先按宿主契约 `retain()` 该会话（引用计数、卸载/切会话释放），挑会话口径收敛到 `pickDirectorySessionId()` |
| 首次为某个会话创建模型目录不再报 `cannot get property "remote.session" without inject` | ✅ 取宿主服务一律经 `ctx.inject(['remote.session'])` 拿到的子 ctx；拿不到退回原 ctx（行为与补丁前一致） |
| 旧宿主（没有 `retain`）保持可读报错，不假装成功 | ✅ `createSessionHold()` 如实返回 false；只对 `resolved no scope` / `resolved no binding` 补一次持有后重试，`inactive context` 不重试 |
| 不能把可选 provider 写进 `inject`，否则没装的机器整块面板 pending | ✅ 用 cordis 的可选依赖用法（子 ctx），依赖缺席只让那条链路 pending，不拖死面板 |
| 不写第二份判据 | ✅ 「是否有人持有」复用 `hasAnyRetention()`；「借会话」仍只有一处实现，并由 `test/panelCss.test.mjs` 的源码扫描钉住 |

### issue #17：「AI 执行」弹窗拿不到「开始」

| 诉求（issue #17） | 本版状态 |
|---|---|
| 1080p / 150%（≈1280×720 视口）下弹窗不得高于视口 | ✅ `.wb-modal` 加 `max-height:min(88vh,900px)` + `overflow-y:auto` |
| 底部「取消 / 开始」常驻可见，不用滚到底 | ✅ `.wb-modal-actions` 改 `position:sticky; bottom:-18px; padding:10px 0 2px`，并补图层底色 |
| 「整页滚动也救不回来」不能再发生 | ✅ `overscroll-behavior:contain` 让滚动落在弹窗内部；内容超出时弹窗自己滚，不再被三层 `overflow:hidden` 裁剪 |
| 回归判据必须会失败 | ✅ `test/panelCss.test.mjs` 新增「视口：AI 提示词弹窗必须有高度上限且内部滚动，底部按钮常驻」用例（删掉任一规则即红），并新增实机双相位探针 `scripts/repro/repro-issue17-modal-overflow.mjs` |

## 3. 变更明细

### 3.1 模型目录（#20，8 文件 / +810 −13）

| 文件 | 变更 |
|---|---|
| `src/client/sessionRef.ts` | 新增 `createSessionHold()`：按使用者**引用计数**持有会话（`retain` / `release`）；已有人持有时不重复 retain；旧宿主没有 `retain` 或 retain 抛错时如实返回 false；open 失败后摘掉登记项，不留"以为持有"的假状态 |
| `src/client/modelDirectorySession.ts`（新） | `pickDirectorySessionId()`：当前会话 → 列表里**已被持有**的会话 → `ids[0]` → 空串；不用"随便挑一个"的兜底去撞宿主判据 |
| `src/client/serviceScope.ts`（新） | `installServiceScope(ctx)` 用 `ctx.inject(['remote.session'], cb)` 拿声明了该 inject 的子 ctx；`serviceScopeCtx(fallback)` 优先用它，依赖缺席时退回原 ctx |
| `src/client/modelCapability.ts` | 原解析逻辑拆成 `resolveModelDirectoryOnce`；新增 `ModelDirectoryRetryHook.ensureScope`，重试判据故意比报错措辞**窄**（只认 `resolved no scope` / `resolved no binding`）；不传钩子时行为逐字不变 |
| `src/client/components/ModelPicker.tsx` | 挑会话走纯函数；render 期仍是纯探测；effect 里 acquire → 解析 → 卸载/切会话释放；点击路径的重算也带 `ensureScope`（acquire 幂等） |
| `src/client/index.tsx` | `apply()` 里 `installServiceScope(ctx)`，`cleanup` 里 `resetServiceScope()` |
| `tsconfig.build.json` | 两个新纯模块进 build 白名单（否则 `lib/` 里没有它，测试 import 不到） |
| `test/modelDirectorySession.test.mjs`（新） | 21 条：挑选顺序、引用计数、宿主已持有不重复 retain、旧宿主回落、单次重试、inactive context 不重试，以及两条结构性源码扫描 |

### 3.2 弹窗视口（#21，2 文件 / +44 −2 + 新增探针脚本）

## 4. 破坏性变更与依赖边界

- **无破坏性变更**：schema 仍为 **19**（不变，不需要迁移）；无新增运行时依赖；`peerDependencies` 区间不变（`^0.1.5-rc.1 || ^0.2.0-rc.1` 一族）。
- **没有新增 `inject`**：`remote.session` 走可选依赖子 ctx，没装 `dsh-client-ui-model-selection` 的机器上车位行为与之前一致（那条链路 pending，面板照常）。
- `#20` 是对**宿主缺陷的规避**，不是长期方案：cordis traceable 服务把服务实例 `ctx` 影射成调用方 ctx 这件事已连同证据写进 issue #19，等宿主修。

## 7. 已知问题

- **桌面端需用户装盘重启后点验本版**（本版只在隔离 3080 实例上验收过）。
- `#20` 是对宿主两个缺陷的**规避**：宿主若再次改 `retain` / traceable 语义，这里会再次失配，长期方案等宿主修。
- `.wb-modal` 仍是 content-box：`max-height` 只夹内容盒，实高 = 上限 + padding(18×2) + border(2)。要"看得见多少就是多少"需改 `box-sizing`，属推迟项。
- 点子页 / 任务详情长文 / 通知 / 提醒 / 微信 / 字典管理的深层 i18n 仍未做（#18 的后续范围）。
