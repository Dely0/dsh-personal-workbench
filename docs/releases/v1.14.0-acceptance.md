## 1. 侧栏入口改用官方槽位（最重要，先验这条）

**判定标准**：侧栏那一行**不再由插件自己画**，而是宿主渲染的官方面板行。

| # | 操作 | 期望 |
|---|---|---|
| 1.1 | 看侧栏（宽屏状态） | 出现一行**「工作台」文字的官方面板行**（不是原来那个自绘 32px 行）。位置紧跟 logoRow / New Session 之后 |
| 1.2 | 点这一行 | 工作台面板出现在**中央区域**（不再覆盖在会话列上）；该行出现宿主自带的激活高亮 |
| 1.3 | 折叠侧栏（切换成 56px rail） | 该行变成 **36px 圆形图标**、与同排其它入口视觉一致；侧栏文字消失 |
| 1.4 | 点顶部会话标题栏的「工作台」按钮 | 面板打开，且**侧栏那一行同时高亮**（两处激活态同源） |
| 1.5 | 在面板里点「返回对话」 | 面板关闭，侧栏行高亮消失 |
| 1.6 | 面板里点任务 → 编辑等操作后关掉再开 | 面板布局正常（`wb-app` 100% 高度没被压扁/溢出） |

**关键回归（旧路径没坏）**：如果本机 DSH 是 0.1.5-rc.1，走的是官方槽位路径；
DOM 降级路径由 `test/entryContract.test.mjs` 的 15 项断言 + 代码保留保证，
**只有把插件装到 0.1.1-rc.1 的机器上才能真正实机验证** —— 这项在本机做不了，已记在已知问题里。

### 互斥验证（需要装兄弟插件才有意义）

本机当前**未安装** `dsh-mnemon` / `task-board` / `ssh` / 皮肤中心，所以：

- 官方槽位路径下互斥由宿主 `activePanelId`（单值）保证，**理论上不再需要**互相摘属性；
- 若要实测：装齐兄弟插件后，两个方向各点一次（先工作台再 mnemon / 先 mnemon 再工作台），
  确认**始终只有一个面板打开、只有一个入口高亮**。

| 4.1.2 | 点「⏸ 暂存」 | 弹框关闭；**可以去 DSH 里干别的事**（不会被每 5 秒拉回来） |
| 4.1.3 | 看「待处理」入口 | 红点仍在；打开后出现在「已暂存（N）」区 |
| 4.1.4 | 点「唤回处理」 | 草稿重新弹出待确认弹框 |
| 4.1.5 | 反复暂存同一份 2 次 | 显示「第 2 次」 |
| 4.1.6 | 查看任务详情的「记录」 | 带 taskId 的草稿（复盘/验收/拆解）暂存后有 **⏸ 草稿暂存** 记录 |

### 4.2 任务草稿的信息量（用户原话痛点的直接验收）

| # | 操作 | 期望 |
|---|---|---|
| 4.2.1 | 让 AI 建一个**任务**草稿（快速录入走澄清即可） | 弹框里能看到：**描述正文**（Markdown 渲染）、**截止时间**、**预计耗时**、**工作区**、**AI 策略**、以及**将同时创建的子任务清单** |
| 4.2.2 | 看弹框底部 | 有 **「回到录入会话」** 按钮（旧版这个类型连回会话入口都没有） |
| 4.2.3 | 点「回到录入会话」 | 工作台关闭，跳到那个 AI 会话 |

### 4.3 文案检查

弹框和「待处理」里**不应再出现**「验证完成后从这里唤回」这类只适配验收类的措辞
（现在应是「做完手上的事再从这里唤回」/「唤回处理」）。

## 5. 复盘记录自动写入团队记忆库

| # | 操作 | 期望 |
|---|---|---|
| 5.1 | 任务详情 → 复盘 → 让 AI 提交复盘草稿 | 弹框底部出现「🧠 同步到团队记忆库」区：**勾选框默认勾上**、可见性**默认 private**，并显示「将写入：N 条（「教训标题 1」、「教训标题 2」…）」 |
| 5.2 | 保持默认 → 确认 | toast 提示「复盘已写回任务，并写入团队记忆 N 条」 |
| 5.3 | 看磁盘 | `~/.dsh/memory/notes/` 多出 N 个 `.md`：文件名 `日期-slug.md`，front matter 里 `kind: "lesson"`、`scope: "private"`、`tags: ["复盘","工作台"]`；正文含**任务 id 与复盘 id**（回链） |
| 5.4 | 看磁盘 | `~/.dsh/memory/queue/` 多出 N 个 `*.json`，`kind: "note"`、`state: "pending"`（等 `dsh-team-memory` 的定时器补传，默认 120 秒） |
| 5.5 | 等一会儿 → `ls_team_memory_search` 搜一条教训的标题 | 能检索到（说明真的上传了；若本机没装/没配 `dsh-team-memory`，条目会留在 notes/queue 里等它） |
| 5.6 | **幂等**：回到那个任务，再让 AI 提一次**同一份**复盘并确认 | toast 提示「这 N 条此前已写入过团队记忆，未重复写入」；`notes/` 条数**不变** |
| 5.7 | **取消勾选** → 确认 | 一个字节都不写（`notes/` 无新增），复盘本身仍正常写回任务 |
| 5.8 | 改可见性为 `team` → 确认另一条复盘 | 新 md 的 `scope: "team"` |

**降级验收**（重要，但需要制造故障）：
把 `~/.dsh/memory` 临时改名或设为只读，再确认一条复盘 —— 期望：
**复盘确认照样成功**，只是 toast 提示「团队记忆降级写入（…）」，并且该条**不会被记成"已写入"**
（恢复后还能补写）。

## 6. 子任务 `type_code` 非法不再静默丢弃

这是本次唯一一条"修复静默数据丢失"的改动，也是最好验的：

| # | 操作 | 期望 |
|---|---|---|
| 6.1 | 在一个澄清会话里，让 AI 提交带 `type_code: "ops"`（字典外的值）的子任务数组 | AI **当场被拒**：工具返回「错误：子项「xxx」的 type_code 不是有效值：ops。合法值：client_meeting / code_impl / …」<br>（工具层直接带**封闭枚举**，AI 不必靠猜） |
| 6.2 | 绕过工具层：直接对数据库/接口造一份含非法 code 的 task 草稿，然后在界面确认 | 弹框关闭后，工作台顶部出现**常驻黄色告警条**：「⚠️ 有 N 项没能创建（其余已正常入册）」，逐条列出标题 + 原因 + 非法值；有「知道了，关闭提示」按钮 |
| 6.3 | 同样的草稿全部用合法 code | 确认后**没有任何**多余提示（零噪音） |
| 6.4 | 非法项下面挂了子项 | 整棵子树都不创建，且**只报父项一条**（不会出现"父没了子还在"的半截树） |

## 7. 横向修复：schema 过新时不再拖死 DSH 启动

不需要你手动验（这是防事故用的），但值得知道它的行为：

数据库 schema 比插件支持的新时（典型成因：`dsh plugin add` 把插件静默回退），
插件现在会**降级空转**：本体照常加载、不注册路由/工具/提醒，
但会往 systemPrompt 注入一条告警 —— 你在 AI 会话里能直接看到
「工作台已停用 + 升级插件到匹配版本即可恢复，不要降级数据库」，**而不是 GUI 都进不去**。

## 9. v1.14.1 复验清单（你报的 4 个问题）

> 先重启 + 硬刷新，然后按下表逐条点一遍。每条都写了"根因一句话"，
> 方便你判断修得对不对（而不只是"看起来好了"）。

| # | 你报的问题 | 怎么验 | 期望 |
|---|---|---|---|
| ① | 点会话标题栏「工作台」→ 会话区**整片空白**，切会话/点侧栏都回不来 | 1) 打开一个会话；2) 点标题栏「工作台」；3) 再点一次；4) 点面板里的「返回对话」；5) 若面板能打开，点侧栏那个「工作台」行 | 面板正常出现在中央区域；关掉后**会话内容原样回来**；任何时候都不出现空白。**这次修法**：不再"探测到就信"，而是注册表 + DOM 两侧都有证据才走官方路径，4 秒内不成立就自动回退 DOM 腿并把入口/覆盖层补上 |
| ② | 草稿弹框出现时背景渐黑 + 闪烁，点「暂存」要连点 5-8 次 | 让 AI 提交任意一份草稿，弹框出现后**点一次**「⏸ 暂存」 | 一次就生效；背景不再变黑/闪烁。**这次修法**：`WorkbenchApp` 之前被挂了两份（覆盖层 + 官方容器），两个实例各自弹框互相盖；现在两种容器严格二选一 |
| ③ | 快速录入下方提示文字被上方输入框遮挡 | 打开「快速录入」 | 提示文字与输入框、勾选项之间都有正常间距，不被压住。**这次修法**：`.wb-hint` 原来只作用于设置页，弹框里根本没样式 |
| ④ | 非法 code 拦截失败 | 让 AI 用 `type_code: "not_a_type"`（或 `999` / `CODE_IMPL`）提交任务草稿 | AI **当场被拒**并收到合法枚举列表；不会落成草稿。**这次修法**：原来字典外的值被静默改写成 `personal`（比"没拦截"更隐蔽 —— 你以为建的是"培训学习"，实际是"个人生活"）；现在封闭枚举严格校验，且回执会回显最终落库的 `type=… priority=…` |

**顺便清一下**：你上次负向测试造出的 5 份 pending 草稿还在「待处理」里
（其中带非法 code 的会走"黄色告警条"那条路）。可以直接在界面里放弃/确认掉，
或者在「待处理」里逐个处理 —— 它们不会自己消失，也不用留给我。
